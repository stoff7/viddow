# Безопасная финализация и поиск инструментов

12 ноября 2026. Продолжение Windows-порта, проверяемое на macOS без Windows-машины.
Изменены две общие границы: фиксация прямого файла/результата ffmpeg и обнаружение
инструментов. Очередь, session v2/history v1, UI и POSIX-владение процессами сохранены.
Job Object пока остаётся отдельным Windows-прототипом.

## Файл, появившийся во время загрузки

Прежняя последовательность `reserve → запись .part → os.replace` могла затереть
файл, созданный другим приложением после reserve. Теперь `finalize_file` выполняет
системную операцию без замены существующего назначения. Конфликт приводит к новой
резервации: например, внешний `video.mp4` сохраняется, наш результат становится
`video (1).mp4`. Повторный конфликт снова выбирает имя. Возвращается фактический
путь для истории, metadata и кнопки показа файла.

macOS использует публичный `renamex_np(..., RENAME_EXCL)` через ctypes; значение
флага и сигнатура сверены с локальным SDK macOS 15.4 (`sys/stdio.h`, `rename(2)`).
Windows использует `os.rename`, который отказывает при существующем назначении:
[контракт Python](https://docs.python.org/3/library/os.html#os.rename).
Прочие POSIX используют link/unlink. Новых пакетов нет. Неподдерживаемая операция
на файловой системе даёт ошибку; опасного fallback на замену нет. Внешние/сетевые
диски и Windows ещё требуют проверки, успешный прогон на APFS не покрывает их.

Отмена проверяется перед каждой попыткой, после успешной фиксации файл сохраняется.
Ошибки убирают собственный исходный `.part` и дополнительные reservation-маркеры,
сохраняя конфликтующий файл. Операция не является гарантией fsync при потере питания.
Изменение относится к двум прежним вызовам os.replace; yt-dlp продолжает собственную
финализацию с `--no-overwrites`, не переписывается в рамках этой задачи.

## Resolver

`platform_support.resolve_tool` принимает только yt-dlp, ffmpeg, ffprobe, deno, node.
Приоритет:

1. Абсолютный исполняемый путь из переменной окружения.
2. Известная папка `bin/` рядом с кодом проекта.
3. Абсолютные каталоги PATH; на macOS дополнительно стандартные Homebrew bin.

| Инструмент | Переменная |
| --- | --- |
| yt-dlp | `VIDDOW_YT_DLP` |
| ffmpeg | `VIDDOW_FFMPEG` |
| ffprobe | `VIDDOW_FFPROBE` |
| Deno | `VIDDOW_DENO` |
| Node | `VIDDOW_NODE` |

Настройки не записываются установщиком в систему. Для native-host переменные
должны быть доступны запускающему его браузеру; надёжнее будущий комплектный bin.
Переменная с пустым/неверным путём — ошибка без fallback. `.cmd`/`.bat` не считаются
инструментами; Windows ищет только `.exe`. Resolver возвращает абсолютный путь,
сохраняя bin symlink, чтобы Homebrew ffmpeg/ffprobe оставались соседями.
Текущий каталог, относительные/пустые элементы PATH исключены из поиска.

Все прежние точки shutil.which в download, inspector, preview, probe, source_auth,
session state и web health переведены на общий resolver. `tools` сохраняет прежние
bool-поля `yt_dlp`/`ffmpeg`: неверная явная настройка даёт false, действие сообщает
конкретную ошибку настройки. Наличие файла не является проверкой его версии/функций.

В yt-dlp передаётся абсолютный `--ffmpeg-location`. Если обнаружены ffmpeg и
ffprobe, они должны иметь согласованные соседние имена: иначе возникает понятная
ошибка вместо незаметного запуска другого probe. Для YouTube выбранный Deno или
запасной Node передаётся абсолютным `RUNTIME:PATH`; неверный явный Deno не скрывается
переключением на Node. Cookie policy остаётся прежней, личные cookies не проверяются.
Контракты параметров: [yt-dlp](https://github.com/yt-dlp/yt-dlp#usage-and-options),
[расположение ffmpeg/ffprobe в upstream](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/postprocessor/ffmpeg.py).

`run_tool` получает отдельный stdin DEVNULL, UTF-8 stdout и best-effort UTF-8 stderr
с заменой ошибочных байтов только в диагностике. Окружение копируется для ребёнка:
PATH очищен от неявного cwd, Python-потоки используют UTF-8. Глобальный PATH не
изменяется. Windows-остановка дерева пока остаётся прежней и не считается готовой.

## Приёмка этой части

Адресные регрессии: внешний файл появляется после reserve в прямой загрузке и
ffmpeg; повторный конфликт; dangling symlink; отказ/отмена; несколько независимых
процессов публикуют разные полные файлы под одним желаемым именем.
Resolver: приоритет override/bin/PATH, неверный override без fallback, отсутствие
cwd/relative/shell-поиска, Homebrew fallback, согласованная пара media tools,
точный путь JS runtime, stdin EOF и Unicode stdout реального инструмента.

Общие тесты ядра/анализа/session/HTTP проверяются завершающим адресным прогоном,
а не после каждой правки. Browser smoke и весь набор автоматически не запускаются.

Результат на macOS: завершающий прогон **71 тест, все прошли**, без пропусков.
В том числе настоящий native-host/HTTP-fixtures, POSIX-отмена дерева, ffprobe
выходного файла с video+audio и ограниченный GIF на локальном HLS. Команда:

```sh
PYTHONPATH=.:tests python3 -m unittest test_platform_support test_download test_inspector test_media_tracks test_source_auth test_server test_native_session test_tracks_offline
```

Loopback-fixtures запускались с разрешением вне sandbox; внешние сайты, личные
cookies и пользовательские профили не использовались. Первый прогон выявил неверное
ожидание нового теста cwd (он не учитывал допустимый Homebrew fallback); проверка
исправлена, завершающий прогон полностью успешен. `git diff --check` прошёл.
Windows/Chrome/Edge и внешние файловые системы не проверялись. Приложение не
переустанавливалось; существующие загрузки, релиз и версия не изменены.
