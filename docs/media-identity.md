# Идентичность выбранного плеера

Контракт первого этапа, 12 ноября 2026. Компоновка карточки, native-протокол и
загрузчик сохраняются. Runtime-зависимости и разрешения не добавляются.

Ключ DOM-кандидата: tabId, случайный токен документа isolated world, frameId,
идентификатор video в WeakMap и его поколение. Поколение меняется при смене
currentSrc/src и событии emptied, включая смену серии без навигации. Перезапуск
документа создаёт новый токен. URL целиком, включая query, участвует в сравнении.
Смена серии без изменения src и без событий media не распознаваема средствами DOM.

Сначала scripting устанавливает reader во всех доступных документах. Затем каждый
родитель опрашивает непосредственные iframe через postMessage с одноразовым nonce.
Ответ связывается с конкретным iframe по event.source === iframe.contentWindow;
токен ответа сверяется с результатами scripting. Сопоставление по URL/порядку не
используется. DOM и postMessage не являются границей безопасности против страницы,
которая намеренно подделывает данные: метаданные считаются недоверенным контентом.
webNavigation не требуется: дерево parentFrameId само по себе не доказывает
видимость контейнера, а нужную связь даёт handshake. Недоступный/неответивший
предок исключает кандидата, скрытый предок исключает всех потомков. Проверяются
hidden, display, visibility, opacity и наличие layout rect; выход за viewport
не означает скрытый плеер. Перекрытие другими элементами пока не определяется.

Два видимых video остаются неоднозначными, даже если один играет. Явно выбранный
сетевой источник получает DOM-метаданные только при точном совпадении currentSrc
и доступных documentId/frameId. Один frame не доказывает соответствие video.
Blob/MSE, редиректы без подтверждённой цепочки и отсутствие currentSrc оставляют
сетевые/DOM-кандидаты раздельными. Новый запрос из другого документа не наследует
заголовки прежнего потока с тем же URL. Группы URL в интерфейсе — только представление.

Перед показом проверяется актуальность токенов документа и поколений media ещё
одним чтением. Ответ старого запроса панели отсекается её revision; событие смены
media сразу очищает картинку. Явный выбор не заменяется фоновым обнаружением;
если его больше нет, метаданные остаются неизвестными до нового выбора.
Постер video не подменяется og:image; изображение страницы показывается отдельно
только когда video вообще не найдено. Происхождение poster/duration связано с ключом.

Приёмка: вложенный cross-origin видимый плеер и скрытый запасной; скрытый предок;
два video одного документа; два видимых iframe; повторяющиеся URL в разных
документах; смена серии, документа, вкладки; поздний ответ; сохранение явного выбора.
Локальная браузерная фикстура проверяет реальную DOM-видимость и event.source.
Потоки фикстуры предназначены для идентичности, не для проверки загрузчика.

## Картинка при нескольких плеерах (уточнение пользователя)

Картинка — обязательная часть визуального выбора кандидатов. Кнопки отдельных
плееров показывают кадр / poster / подписанную заглушку, сохраняя media key.
Приоритет выбранного изображения: подтверждённый frameImage → poster данного
video. PageImage не участвует в этом fallback. В карточке сетевого потока
изображение появляется лишь при точном и однозначном DOM-сопоставлении; отсутствие
доказанной связи подписано явно. Кадр, постер и общий постер страницы не смешиваются.

Снимается только уже декодированный кадр (readyState >= 2, videoWidth/Height > 0),
без play/seek. Canvas уменьшается до 320×180 с сохранением пропорций; JPEG вместе
с data URL ограничен 128 КиБ. Canvas освобождается, CORS/пустой кадр/превышение
лимита возвращают отсутствие frameImage. Снимок обновляется при loadeddata,
pause/seeked и явном выборе; непрерывная запись видео не ведётся.
Для одной проверки панели кадры запрашиваются максимум для 24 кандидатов (приоритет у видимых в списке, при прокрутке окно
обновляется) плюс выбранного, включая выбранного за пределами этого окна. Остальные сохраняют
poster/заглушку до выбора. Все идентичности учитываются; лимит не делает выбор
однозначным. Изображения существуют только в памяти панели и результатах scripting;
не идут в native state, историю или диагностический журнал.

Браузерная приёмка расширена: лента из 30 video без poster, явный выбор 30-го,
картинка выбранного, смена зелёного кадра на синий, CORS fallback на poster,
сохранение paused/currentTime, сетевой запрос с documentId/frameId. Фикстура
проверяет механику ленты, а не поддержку настоящего X. Связь blob/MSE с manifest
и платформенный extractor остаются отдельной незавершённой задачей.
