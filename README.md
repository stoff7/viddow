# Viddow

Локальный загрузчик видео на Python. Основной интерфейс — постоянная боковая панель расширения Chromium; веб-страница и CLI доступны дополнительно.

Windows-порт в разработке: [технический этап для Windows 11 x64](docs/windows-development.md).
Регистрация и прототип управления процессами подготовлены; Windows-совместимость
ещё не подтверждена. Опубликованный v3.4.0 остаётся прежним macOS-релизом.

## Релиз v3.4.0

[Скачать v3.4.0](https://github.com/stoff7/viddow/releases/tag/v3.4.0) · [Что изменилось](docs/releases/v3.4.0.md).
Архив содержит расширение и локальный Python-загрузчик. Распакуйте его в постоянную
папку и выполните установку ниже; `yt-dlp` и `ffmpeg` устанавливаются отдельно.
Новый интерфейс пока не прошёл автоматические и браузерные проверки.

## Возможности

- Скачивание прямых ссылок на файлы средствами стандартной библиотеки Python.
- Загрузка HLS/DASH-потоков через `yt-dlp` или, если его нет, `ffmpeg`.
- Загрузка страниц с видео через `yt-dlp`, если он поддерживает источник.
- Компактные карточки видео: превью и длительность при наличии, выбор качества и озвучки рядом с кнопкой «Скачать».
- Автоматическая подготовка одного выбранного источника; раннее нажатие «Скачать» с возможностью отмены.
- Поиск ссылок на видео в HTML: по адресу страницы, из вставленного кода или файла.
- Перехват HLS/DASH-запросов вкладки расширением и передача заголовков запроса загрузчику.
- Веб-интерфейс со светлой/тёмной темой и адаптацией для телефона.
- Общая очередь всех вкладок расширения: лимит, отмена, повтор, фильтры и очистка завершённых.
- Папка сохранения, параллелизм и тема в настройках панели.
- История расширения между запусками: результаты, даты, пути файлов и повтор со свежей страницы.
- Прогресс, отмена, повтор и «Показать файл» в карточке видео; подбор свободного имени файла.
- Подтверждение отдельных HLS-дорожек через ffprobe и объединение видео/звука одного ролика X.

По умолчанию файлы сохраняются в `~/Downloads`.

В рабочей ветке добавлены [замеры и ограничение параллелизма](docs/download-optimization-contract.md):
`VIDDOW_FRAGMENT_BUDGET` задаёт бюджет fragment workers одного host (default 32).
Прямые HTTP-файлы на POSIX могут продолжаться после временного обрыва при
подтверждённой версии объекта; отмена удаляет части, автозагрузки после запуска нет.
HLS/DASH между запусками и Windows persistence пока не поддерживаются.
Удалить неактивные части: `python3 download.py --clear-incomplete -o /absolute/output`.
Результаты сравнения и ограничения — в [отчёте](docs/session-report-2026-11-13-download-optimization.md).

## Требования

- Python 3.9 или новее.
- Для страниц с видео — `yt-dlp`.
- Для объединения отдельных видео- и аудиодорожек — `ffmpeg`; он также используется как запасной загрузчик потоков.

Установка инструментов на macOS через Homebrew:

```sh
brew install python yt-dlp ffmpeg
```

Инструменты ищутся по явному абсолютному пути, в `bin/` проекта, затем в допустимых
каталогах PATH и стандартных Homebrew bin. [Настройка и контракт](docs/platform-tools-and-publication.md).
В режиме перехваченного потока загрузчик использует `yt-dlp --impersonate chrome`:
установленная сборка yt-dlp должна поддерживать этот режим.

## Боковая панель расширения на macOS

1. Откройте управление расширениями браузера, например `chrome://extensions`.
2. Включите режим разработчика и загрузите распакованное расширение из папки `extension`.
3. В терминале из папки проекта выполните `python3 install_native_host.py`.
4. Обновите расширение кнопкой ⟳ на странице управления расширениями. Закрепите его значок на панели браузера.
5. Откройте страницу с видео и нажмите значок Viddow: боковая панель остаётся рядом с сайтом. Запускать `server.py` не нужно.

Журнал подключения и ошибок интерфейса: **Настройки → Журнал диагностики**. Его можно скопировать или очистить. При раннем сбое он появится сразу в панели. Последние 200 событий хранятся до перезагрузки расширения, без ссылок, cookies и заголовков. Подробнее: [диагностика](docs/extension-diagnostics.md).

В нижней навигации:

- **Видео**: компактные карточки подтверждённых плееров текущей вкладки. В карточке — собственное превью или заглушка, длительность, качество и выбор звуковых дорожек. Нажмите превью, чтобы выбрать и подготовить видео, либо «Скачать», чтобы начать после подготовки. Полный адрес, параметры, повторный анализ и прямое скачивание доступны в меню **⋯**. Неподтверждённые сетевые адреса остаются в раскрываемом блоке «Найденные адреса».
- **Загрузки**: общая очередь всех вкладок и окон, включая видео, исчезнувшие со страницы. Здесь доступны прогресс, отмена, повтор, фильтры, очистка записей и «Показать файл». Счётчик **✓** отмечает завершения до просмотра очереди. Очистка сохраняет файлы.
- **Ссылка**: ввод HTTP(S)-ссылки с анализом или прямым скачиванием без выбора качества. При прямом скачивании открывается общая очередь.
- **Настройки (⚙)**: папка сохранения, 1–8 одновременных загрузок и сеанс YouTube. Изменения настроек загрузчика применяются, когда очередь не активна. Тема переключается в шапке; настройки сохраняются между запусками.

При обнаружении однозначного плеера расширение автоматически подготавливает видео. При нескольких плеерах сначала выберите нужное превью. Если страница не поддерживается yt-dlp, подготовка проверяет актуальные HLS/DASH в существующих пределах. Результаты с разными источниками остаются отдельными карточками; кадр соседнего плеера не используется.

Основное действие — **«Скачать»**. Во время подготовки нажатие запоминается: карточка показывает «Начнём после подготовки» и отмену. Без нажатия полный ролик не скачивается. Неизвестный состав дорожек или только звук не удовлетворяют автоматическому намерению скачать видео; такие форматы можно выбрать явно. При нескольких озвучках отметьте нужные дорожки или явно выберите видео без звука.

Очередь, прогресс, ошибка и результат появляются в той же карточке. Только завершённое задание получает **«Скачано»** и действие **«Показать файл»**; имя и путь доступны в ⋯. Если файл удалён или помощник отключён, показ файла недоступен. Обновление прогресса не пересоздаёт карточку. При исчезновении плеера результат остаётся в общей очереди.

Анализатор общий для всех панелей native-сеанса. После подготовки другого видео прежние форматы нужно получить снова; уже добавленные задачи продолжают работу. Для GIF ffmpeg может прочитать начало источника: до двух секунд, восьми кадров и 128 КиБ на окончательное превью. Ошибка картинки не блокирует скачивание. Обходы плееров объединяются, кадры кешируются; фоновые снимки скрытой панели не выполняются. Контракты: [карточки](docs/helper-card-contract.md), [завершение](docs/download-completion.md), [дорожки X](docs/x-tracks-and-preview.md), [производительность](docs/player-performance.md).

Подготовку можно отменить. Для исходной страницы таймаут — 30 секунд; запасная партия ограничена шестью актуальными кандидатами, по два одновременно и до 12 секунд на каждый. Она не повторяет неподдерживаемую страницу. Анализ общий для панелей текущей сессии; новый ручной выбор сильнее рекомендации. Свежий наблюдаемый адрес проверяется даже без DOM-привязки; подтверждённо скрытые и прежние источники исключаются. Источник, ID формата и заголовки копируются в задачу. Отложенное нажатие отменяется при смене вкладки/документа, выбранного media или native-сеанса; уже добавленная очередь продолжает работу. Подробнее: [автоматическая подготовка и GIF](docs/automatic-video-preparation.md), [качество и озвучки](docs/quality-selection.md).

Закрытие панели сохраняет очередь и Native Messaging-канал в фоновом процессе расширения. Закрытие браузера или перезагрузка расширения останавливают незавершённые задачи и дочерние процессы; частичные файлы удаляются, готовые сохраняются. История расширения сохраняется между запусками; незавершённые задачи после нового подключения отмечаются как «Прервано», автоматического повтора нет. При разрыве связи панель показывает ошибку и кнопку «Подключить»; задачи прежней сессии не отправляются заново.

Восстановленные записи показывают прошлый результат, дату и путь. Если файл удалён, панель пишет «файл не найден»; «Показать файл» недоступно. «Очистить завершённые» удаляет записи из истории, сохраняя файлы и текущие загрузки.

У записи с безопасно сохранённой исходной страницей есть **«Повторить со страницы»**: панель получает свежие форматы, после чего вы подтверждаете скачивание. Старые заголовки, CDN-ссылка и ID форматов не используются. Для прямой ссылки или страницы, чьи параметры нельзя безопасно сохранить, нужно вставить новую ссылку. В истории остаются только безопасные метаданные; полный адрес загрузки, Cookies/Authorization, подписанные query и сырой текст ошибок не сохраняются. Настройки и история принадлежат конкретному профилю браузера. Контракт и проверки: [постоянная история](docs/persistent-history.md).

Для работы нужны [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) и [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging). Манифест требует Chrome API 116+. Разрешения: `sidePanel`, `nativeMessaging`, `storage`, `webRequest`, `scripting` и доступ к HTTP(S)-источникам через `<all_urls>`. Полные адреса и заголовки сохраняются в памяти/сессионном хранилище для текущей загрузки, а в постоянные настройки не записываются.

Установщик регистрирует хост в найденных каталогах Chrome, Chromium, Vivaldi, Brave, Edge и Яндекс Браузера. **До изменений панели v3.4.0 сквозной сценарий проверялся на macOS с Google Chrome for Testing 156.0.8078.4**; остальные браузеры требуют отдельной проверки поддержки sidePanel. После перемещения проекта загрузите расширение заново и повторите установку хоста: регистрация и ID зависят от пути.

Перед обновлением дождитесь завершения загрузок: перезагрузка расширения прерывает native-сеанс. Обновите файлы в прежней папке, затем распакованное расширение в управлении расширениями и саму страницу с видео, чтобы заменить внедрённый скрипт. Перерегистрировать хост при прежнем пути не требуется: он запускает Python из этой папки. Если помощник не найден, повторите установку и нажмите «Подключить». Наличие yt-dlp/ffmpeg показано в настройках; сообщения ошибок содержат команду установки.

Для изолированной проверки предусмотрена регистрация только в заданном каталоге данных браузера (без записи в пользовательские профили):

```sh
python3 install_native_host.py --user-data-dir /tmp/viddow-test-profile
```

Этот браузер должен запускаться с тем же `--user-data-dir`. Протокол и границы очереди описаны в [docs/extension-control.md](docs/extension-control.md), результаты — в [docs/verification.md](docs/verification.md).

## Веб-интерфейс

Из папки проекта:

```sh
python3 server.py
```

Откроется `http://127.0.0.1:8765/`. Вставьте ссылку на страницу с видео, файл или поток и нажмите «Скачать». Задача появится в списке; одновременно выполняются две загрузки, остальные ждут очереди.

В «Параметрах загрузки» можно задать имя и тип ссылки. Режим «Страница с видео» сразу передаёт адрес в yt-dlp, обходя предварительный запрос urllib. В автоматическом режиме ошибки HTTP 401/403/405/429 для предполагаемой страницы также дают возможность попробовать yt-dlp.

В списке можно отменить задачу, повторить ошибочную/отменённую загрузку и скопировать путь готового файла. Очистка списка сохраняет файлы на диске. При потере связи интерфейс показывает сообщение и автоматически восстанавливает опрос.

«Поиск в HTML» открывает дополнительный инструмент: загрузка исходного кода по адресу, вставка HTML или перетаскивание файла, выбор найденных ссылок, копирование ссылок и команды для CLI.

Другой порт и запуск без открытия браузера:

```sh
python3 server.py --port 8766 --no-browser
python3 server.py --workers 3 -o ./downloads
```

Сервер слушает только `127.0.0.1`. Параметр `--workers` принимает значения от 1 до 8. При открытии `video-links.html` как локального файла доступен разбор HTML, но скачивание через сервер недоступно. Для такого запуска рядом с HTML должна оставаться папка `web`.

## CLI

```sh
python3 download.py 'https://example.com/video.mp4'
python3 download.py 'https://example.com/watch/123' -n 'Моё видео'
python3 download.py 'https://example.com/watch/123' --source-kind page
python3 download.py 'https://example.com/master.m3u8' --referer 'https://example.com/watch/123'
python3 download.py 'https://example.com/video.mp4' -o ./downloads
python3 download.py --help
```

Можно передать несколько адресов: CLI обработает их последовательно.

## Проверка

Для v3.4.0 выполнена только сверка новых UI-правок по исходному коду. Тесты, syntax-check и браузерные сценарии после смены интерфейса не запускались. Описанные ниже smoke-сценарии относятся к прежней панели; их селекторы требуют актуализации. Старые результаты не подтверждают текущий интерфейс.

Тесты Python используют стандартную библиотеку, временные каталоги и HTTP-серверы на loopback. Пользовательская папка загрузок не затрагивается, внешние сайты не запрашиваются:

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_streams.mjs tests/test_formats.mjs tests/test_history.mjs
```

Браузерный тест дополнительно требует Node.js, Playwright и Chromium. Playwright можно установить отдельно от проекта, например во временную папку:

```sh
npm install --prefix /tmp/viddow-browser-check --no-package-lock playwright
/tmp/viddow-browser-check/node_modules/.bin/playwright install chromium
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/extension_smoke.cjs
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/extension_native_smoke.cjs
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/browser_smoke.cjs
```

`extension_smoke.cjs` проверяет настоящую боковую панель и webRequest с подменённым native-портом: команды, смену вкладки, темы и 320–400 px, ранние превью/длительность, автоматическую подготовку без дублей между панелями, сохранение выбранного источника, ошибки до ready, таймаут и reconnect без повторов, миграцию/повреждение истории, неизвестную версию и ошибки записи. `extension_native_smoke.cjs` использует настоящий зарегистрированный хост и локальное видео: MP4, страницу/HLS через yt-dlp, очередь, выбор качества/двух языков с ffprobe, два окна, закрытие/открытие панели, смену папки, ошибки, reconnect и остановку хоста/yt-dlp после закрытия браузера. Затем браузер действительно перезапускается с тем же профилем: проверяются восстановление результатов/прерванных задач, настройки, удалённый файл, повтор с новой ссылкой и отсутствие секретов в JSON истории. Нужны yt-dlp, ffmpeg и ffprobe; расширение проверяется в видимом окне современного тестового Chromium. Скрипт устанавливает хост исключительно во временный профиль и удаляет профиль/файлы после проверки. Окна Finder по умолчанию не открываются: реальный `reveal` включается только явным `VIDDOW_TEST_FINDER=1`; обычный Python-тест проверяет его с подменой системного вызова.

`browser_smoke.cjs` проверяет дополнительный веб-интерфейс: скачивание, отмену, повтор, HTML-поиск, восстановление связи и адаптивность. Скриншоты находятся в `viddow-extension-check`, `viddow-native-check` и `viddow-ui-check` внутри системного временного каталога. Для уже установленного Chromium можно передать путь к исполняемому файлу через `CHROMIUM_PATH`; каталог скриншотов меняется через `VIDDOW_ARTIFACTS`.

## Текущие ограничения

- Разбор HTML не выполняет JavaScript страницы; динамические потоки может обнаружить расширение при воспроизведении видео.
- Поддержка источника зависит от сайта, авторизации и возможностей установленной версии yt-dlp; скачивание любого видео не гарантируется.
- Очередь веб-сервера и очередь расширения независимы. `--workers` относится к веб-серверу, настройка панели — к расширению.
- Отмена сетевого чтения может ждать до таймаута (30 с); в это время задача отмечена как останавливающаяся. На POSIX отмена внешнего инструмента останавливает также его дочерние процессы.
- История расширения сохраняется между запусками браузера. Самостоятельная веб-очередь остаётся в памяти сервера. Возобновление частичных файлов не реализовано.
- Плейлисты отключены: загрузчик передаёт yt-dlp параметр `--no-playlist`.
- Установщик расширения и показ файла в Finder рассчитаны на macOS.
- Большие сессии с очень длинными URL упираются в лимит Native Messaging 1 МиБ на сообщение хоста. Разбиение снимков очереди на части пока не реализовано; поддержку таких очередей не заявляем.

Локальный список ссылок `urls.txt`, кэш Python и файлы окружения исключены из Git.


Сквозной журнал расширения и загрузчика: `logs/viddow.jsonl` в папке проекта
(одна резервная копия `.1`, файлы исключены из git). В нём видны получение адреса,
причина отбора, анализ, превью, старт и результат загрузки. Записываются только
коды и непрозрачные ID; сырые URL, cookies и заголовки не сохраняются. Журнал
начинает пополняться после подключения обновлённого native-host.

Повторные ошибки одной попытки загрузки отображаются одной карточкой в «Загрузках».
Внутри «Ошибки попытки» доступны причины и время; после успешного повтора предыдущие
ошибки остаются подробностями той же карточки. Связь сохраняется в истории.
