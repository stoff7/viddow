# X: дорожки выбранного видео и короткое превью

12 ноября 2026. В живом журнале анализы 19ff0731… и 6d95ae77… принимают три
источника выбранного media ID, каждый возвращает один формат. Задания 11–13
завершаются, а все запросы preview дают preview_error. Код разрешал автоматически
скачивать unknown: это мог быть отдельный аудиоплейлист.

Проверка публичных адресов из сообщения без cookies показала: yt-dlp сообщает
vcodec/acodec=null для обоих отдельных плейлистов avc1 и mp4a. ffprobe на видео
подтвердил h264 1280×720. Master содержит отдельные video и три качества audio.
Проверка прежнего GIF-командного пути дала файл 158349 байт: -fs не является
жёстким пределом размера, а base64 увеличивает размер ещё примерно на треть.

## Контракт до правки

- unknown и audio не удовлетворяют автоматическому намерению «Скачать видео».
  Явный ручной выбор аудиоформата остаётся допустимым.
- Отдельный неизвестный HLS проверяется ffprobe с ограничением времени,
  размера анализа и вывода. Неизвестное не превращается в видео по имени URL.
- Дорожки объединяются только по точному X namespace/media ID. Исходные URL,
  query и заголовки остаются частными и принадлежат своим форматам. У других
  источников прежний запрет объединять по домену/названию сохраняется.
- Разные битрейты звука одного X media/языка/канальности — варианты качества;
  рекомендуется лучший. Разные языки сохраняются для явного выбора.
- Загрузка использует существующий yt-dlp и его load-info-json; подготовленные
  сведения передаются только внутри native host, временный JSON удаляется,
  не пишется в историю, не встраивается в файл и не принимается из панели.
- Превью читает не более двух секунд, до восьми кадров. Палитра/размер уменьшены,
  проверяется размер вместе с base64. Кадр/постер выбранного DOM-плеера может
  показываться сразу при подтверждённой связи с CDN-группой. Соседний кадр не брать.

## Приёмка

Фикстура: отдельные fMP4 HLS video-only и audio-only, generic yt-dlp даёт unknown.
Проверить классификацию, объединение только одного media ID, per-track headers,
итоговый файл с video+audio через ffprobe, реальное GIF в лимите; unknown/audio
не скачиваются сами. Сохранить отмену, очередь, ручной выбор и приватность.

Источник API: [официальный yt-dlp — загрузка из info-json](https://github.com/yt-dlp/yt-dlp#embedding-examples).

## Реализовано и проверено

media_tracks.py проверяет неизвестный single-format HLS через ffprobe (до 3 с,
1 МиБ probesize, 1 с analyzeduration) и формирует частный набор дорожек только
одного X ID. Журнал candidate_done содержит video/audio/unknown_count, probe
имеет отдельные события. Меньшие битрейты звука одного языка/канальности не
мешают выбрать старший; разные языки остаются для явного выбора.

Временный info-json имеет режим 0600, содержит только выбранные форматы и
не содержит webpage_url, чтобы ошибка выбранной загрузки не запустила скрытое
повторное извлечение другого ролика. Prepared info не принимается из панели,
передаётся от Inspector через JobManager в существующий yt-dlp runner.

GIF: до 2 с и 8 кадров, 160×90, палитра 32 цвета. Ограничение применяется к
окончательному data URL. При доступном собственном постере/кадре панель показывает
его по подтверждённому X media ID, не ожидая GIF. Только звук больше не получает
текст «Видео готово к скачиванию».

- 57 JS-тестов, 59 Python-тестов без TCP и одна настоящая offline media-проверка
  прошли. Синтаксис JS/Python и diff --check чистые.
- Offline-проверка использует настоящие ffprobe, yt-dlp, ffmpeg и раздельные
  fMP4 HLS, но заменяет сетевые URL локальными file URL только в тесте.
  Итоговый MP4 содержит video и audio, data URL GIF — 21254 байта (<128 КиБ).
  Артефакты: /tmp/viddow-tracks-proof/{selected.mp4,preview.gif,proof.json}.
- Пять native_session-тестов завершились ошибкой setUp при bind(127.0.0.1):
  PermissionError в sandbox. Проверки браузера и реального X после правки
  не выполнены. Последний запрос внешнего modern-web-guidance отклонён
  автоматическим review из-за лимита сервиса; это не отказ по безопасности кода.
