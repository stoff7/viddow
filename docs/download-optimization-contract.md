# Контракт оптимизации загрузок

13 ноября 2026. Область: Python downloader, один JobManager/native-host;
отдельный web-host имеет собственный бюджет. UI, native protocol v2 и история
не меняют семантику. Новых зависимостей, daemon и второго stream downloader нет.
Windows Job Object остаётся отдельным прототипом.

## Измерения

`download_timing` использует monotonic и существующий allowlist журнала.
`attempt_tag` объединяет явные повторы одной карточки; случайный `run_tag`
различает конкретные исполнения. Process events внутри загрузки имеют оба ID.

| Поле | Значение |
| --- | --- |
| queue_ms | От постановки до запуска runner |
| preparation_ms | От запуска до первого наблюдаемого положительного счётчика байтов |
| first_byte_ms | От постановки до первого наблюдения байтов, включая очередь |
| transfer_ms | От первого наблюдения до начала postprocess либо ошибки/конца |
| finishing_ms | Postprocess, перемещение и metadata до возврата результата |
| elapsed_ms | От постановки до результата/ошибки/отмены |
| observed_bytes | Сумма максимумов downloaded_bytes по дорожкам в этом исполнении |
| fragment_workers | Выделенная статическая доля fragment workers |

Для прямого HTTP наблюдается чтение тела. Для yt-dlp это время получения
progress callback, верхняя оценка времени фактического первого байта.
Счётчик yt-dlp может включать продолженный префикс и не равен передаче по сети.
Он не измеряет повторные байты; `reused_bytes` в recovery event — проверенный
префикс прямого HTTP. Retry count и TCP connections не синтезируются.
Если сигнала нет, соответствующего поля нет. Для ffmpeg fallback входные байты
не видны: размер mux-выхода не используется вместо сетевого счётчика.
Analysis и preview имеют прежние отдельные ID и elapsed_ms; они не прибавляются
к стадиям download повторно. URL, пути, заголовки, исходные ошибки и пиксели в
новые события не попадают.

## Параллелизм и приоритет

`VIDDOW_FRAGMENT_BUDGET=1..64`, default 32. Одновременно запускается не более
`min(workers, budget)` задач. Каждая при старте получает
`min(16, floor(budget / min(workers, budget)))` workers. Доля фиксирована до
завершения процесса; при изменении нагрузки yt-dlp не перезапускается.
Незанятая доля не раздаётся адаптивно. Configure доступен только без активных
задач; FIFO и удержание слота до выхода runner сохранены.

Default сохраняет прежние 16 фрагментов при 1–2 загрузках, ограничивая общий
рост при 3–8 загрузках. Уменьшенные доли остаются конфигурацией для сравнения:
локальная матрица не подтвердила отсутствие регрессий при меньшем default.
Это бюджет значений `--concurrent-fragments` для поддерживаемых yt-dlp
протоколов, не универсальный предел внутренних потоков или точный лимит TCP.
В установленном yt-dlp live DASH generator может округлять доли вверх по
нескольким дорожкам; этот режим не измерен. Manifests, redirects, повторы и
preparation учитываются отдельно.
Глобальный лимит между процессами/компьютерами и произвольное объединение CDN
доменов не реализованы: для этого нет подтверждённого source identity.

В native-сеансе manager и Inspector разделяют WorkScheduler. Явные загрузки
никогда не ждут GIF. Основной анализ исходной ссылки также не ждёт GIF.
Необязательные fallback-кандидаты и GIF используют один background slot.
При активной загрузке новая background-операция ждёт максимум 2 секунды;
это ограничивает задержку первого скачивания и исключает бесконечное голодание
фона. Уже запущенный ffmpeg не перезапускается. Отмена проверяется при ожидании.

Существующее single-flight превью остаётся в памяти конкретного source ID
и analysis generation; новый анализ и смена browser auth инвалидируют контекст.
После отказа доступа/истечения ссылки/исчезновения источника native-сеанс
запрещает повторное использование выбранных форматов до свежего анализа.
TTL не считается доказательством действительности URL; дискового кеша formats нет.

## Повторы

Прямой HTTP: максимум 3 GET-попытки, без внешнего умножения; HEAD проверки версии
не передают тело. Ожидание retry ограничено recovery window 60 секунд от первой
временной ошибки. Socket timeout 30 секунд. Успешная длительная передача не
обрывается только из-за общей длительности. 408/429/500/502/503/504 и сетевой
обрыв могут повторяться; TLS validation, 401/403, format/disk/permission errors
не повторяются. Retry-After в секундах или HTTP-date соблюдается, если помещается
в оставшееся окно; иначе попытка завершается. Ожидание прерывается cancel.

HLS/DASH используют существующий yt-dlp: retries=1, fragment-retries=2,
extractor-retries=1, растущие retry-sleep, abort-on-unavailable-fragments.
Внешнего повторного запуска поверх этих попыток нет. Весь TemporaryDirectory
живёт до конца этого исполнения. Watchdog прекращает подготовку/передачу после
60 секунд без новых наблюдаемых байтов; postprocess освобождён от этого watchdog.
Retry-After/число внутренних повторов yt-dlp не выдумываются по stderr.

## Части между задачами и перезапусками

Реализована консервативная поддержка **прямого HTTP**, когда ссылка явно direct
либо имеет известное файловое расширение. Прочие auto ответы сохраняют прежний
путь. На POSIX части располагаются в `<output>/.viddow-parts/<hash>/`, mode 0700.
В `state.json` только версия схемы, длина, число подтверждённых байтов и SHA-256;
нет URL, cookies, headers, имени результата, prepared info-json или raw ETag.
Ключ включает хеш полного URL и контекста запроса: новая подписанная ссылка
или другая авторизация не подставляются в старые части.

Восстановление разрешено только для strong ETag, известной длины и identity
content encoding. SHA-256 проверяет локальный префикс; HEAD подтверждает ту же
версию/конечный URL/контекст. GET использует Range и свежий If-Range. Проверяются
206, точный Content-Range, длина остатка и strong ETag ответа. 200 полностью
заменяет собственный префикс; неверный 206 отвергается. Изменённый объект,
слабый/исчезнувший validator и неподдерживаемый HEAD ведут к новому файлу.

Durable checkpoint каждые 8 МиБ: flush/fsync данных перед атомарной записью
state. После аварии хвост после checkpoint отбрасывается. При обработанном
временном обрыве checkpoint включает весь полученный префикс. Запуск приложения
не создаёт загрузок: только новая явная команда с тем же подтверждённым контекстом
может продолжить. Cancel удаляет текущие части; pause не введён. Готовый файл
сохраняется при поздней отмене. История не стала хранилищем сетевого контекста.

HLS/DASH между исполнениями **не дописываются**. Manifest, название и длительность
не доказывают версию всех сегментов/init data, особенно live/истёкших URL. Для
этого нужен отдельный доказанный протокол версионирования сегментов; сомнение
приводит к новой отдельной загрузке. Это явная граница восстановления, а не
обещание полноценного stream resume. На Windows persistence отключён до
проверки ACL и process ownership; внутритасковые повторы работают в ephemeral
workspace, существующий Job Object-прототип не интегрирован.

## Владение, квота, диск и удаление

POSIX flock удерживается всё время владения. Совпавшие одновременные запросы
получают отдельные части; cleanup не удаляет активные. Квота неактивных частей
5 ГиБ, TTL 7 дней, максимум 128 записей. Активная загрузка может превышать квоту,
но её незавершённый результат тогда не сохраняется. Проверка свободного места
для прямого файла выполняется перед записью остатка и не гарантирует отсутствие
позднего ENOSPC. Существующие конечные файлы никогда не удаляются cleanup.

Удаление неактивных частей:

```sh
python3 download.py --clear-incomplete -o /absolute/output/folder
```

Native command `clear_incomplete` и локальный POST `/partials/clear` с JSON
предоставляют то же действие с прежними проверками session/origin.
Текущий UI не переписывается.

Для yt-dlp `VIDDOW_TEMP_LOCATION=system|destination`, default system. Destination
использует управляемый временный каталог mode 0700 на POSIX рядом с результатом;
он очищается после исполнения. В нём допускается ephemeral prepared JSON,
но он никогда не попадает в persistent parts. Default не меняется по сравнению
маленьких файлов на одном локальном диске; внешний диск требует отдельного замера.
CHUNK_SIZE и finalization без перезаписи сохранены.

## Проверяемые критерии

- Матрица 2/4/8/16, 1/2 задачи: корректные видео+аудио по ffprobe, длительность,
  время, число ошибок и серверные запросы/байты; MP4 отдельно.
- Cold/warm анализ, GIF on/off, приоритет on/off и system/destination temp
  сравниваются отдельным harness; локальные ограничения не выдаются за CDN.
- Отмена освобождает очередь и ожидания; background имеет конечную отсрочку.
- Обрыв direct реально уменьшает повторную передачу, включая другой Python
  процесс; изменённый объект, неправильный Range и локальная порча не смешиваются.
- Квота/cleanup сохраняют активные и готовые файлы; на старте нет автозагрузки.
- Windows-порт и его пользовательские материалы сохраняются; платформенная
  готовность без исполнения на Windows не заявляется.

Официальные механизмы сверены с установленным yt-dlp 2026.10.21 (`--help` и
исходники progress hooks/fragment state) и [официальной документацией](https://github.com/yt-dlp/yt-dlp#readme).
Проверки Range/If-Range следуют [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-range).
Результаты и действительные пределы проверки будут записаны в отчёте сессии.
