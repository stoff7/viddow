# План завершения и развития Viddow

Дата: 11 ноября 2026. Основной интерфейс — боковая панель расширения.
Цель ближайшего этапа: надёжное управление загрузками всех вкладок из панели,
без ручного запуска веб-сервера.

## Статус 11 ноября 2026

Этапы **1–4 выполнены локально** с сохранением существующей реализации.
37 Python-тестов, 7 JS-тестов и три browser smoke прошли.
Этап 4: [качество/дорожки и результаты](../docs/quality-selection.md).
Реальный путь sidePanel → Native Messaging → файл подтверждён в отдельном профиле.
[Подробный отчёт и границы](../docs/verification.md),
[остаточные вопросы](open-issues.md). Push/merge не выполнялись.
Ниже сохранены исходные критерии и план следующих этапов.

## Правила продолжения

1. Сначала завершить текущую реализацию. Новую платформу, фреймворк или daemon
   не добавлять без конкретной необходимости.
2. Каждый этап должен закончиться проверяемым поведением. Успех Python-тестов
   не заменяет проверку настоящего расширения, а браузерный mock — реальную загрузку.
3. Сохранять полные URL, query-параметры и заголовки. Не удалять токены ради
   «дедупликации»: похожие адреса могут обозначать разные видео/дорожки.
4. Рабочая ветка — `feat/download-workspace`. Сохранить незакоммиченные изменения.
5. Закрытие панели сохраняет работу, закрытие браузера пока останавливает задачи.
   Постоянная история и восстановление после перезапуска — отдельный этап.
6. Одна очередь **всех вкладок расширения**. Очередь отдельно запущенной
   веб-версии пока другая; не обещать пользователю синхронизацию между ними.

## Карта кода

| Область | Файлы | Ответственность |
|---|---|---|
| Панель | `extension/popup.html`, `popup.css`, `popup.js` | Вкладка, найденные потоки, ручная ссылка, задачи, настройки |
| Фоновый процесс | `extension/background.js` | webRequest, сессионное хранилище, один connectNative, запросы/ответы |
| Потоки | `extension/stream-model.mjs` | Полный URL, свежие заголовки, ограничение 30, группировка для показа |
| Протокол | `native_host.py`, `native_session.py` | Фреймы JSON, session v2, команды и снимки очереди, EOF |
| Очередь | `jobs.py` | Лимит, queued/running/cancelling, отмена, повтор, настройки в idle |
| Валидация | `contracts.py` | Общая проверка URL, заголовков и полей запроса |
| Загрузка | `download.py` | HTTP, yt-dlp, ffmpeg, имена, временные файлы, остановка процессов |
| Веб-версия | `server.py`, `video-links.html`, `web/` | Дополнительный интерфейс и самостоятельный HTTP JobManager |

## Этап 1. Стабилизировать текущий код — выполнить первым

### Работа

- Диагностировать timeout смены вкладки в extension_smoke. Проверить активный
  tab/window до и после клика по UI, различить ошибку теста и ошибку панели.
- Устранить нестабильность теста HTTP 413 при раннем закрытии соединения.
- Пройти оставшуюся часть extension_smoke: другая вкладка, ручная ссылка,
  разрыв native-порта, отсутствие необработанных JS-ошибок.
- Проверить сохранность незавершённых задач в UI после закрытия/открытия панели.
- Проверить граничные состояния соединения и session ID; при необходимости
  добавить узкие тесты выявленных дефектов, а не большой новый набор «на всякий случай».

### Проверки и критерий завершения

- Полный Python-набор проходит: сейчас 23 теста, новые — только по найденным дефектам.
- 4 теста stream-model проходят.
- extension_smoke доходит до финального PASS, не отключая проверку смены вкладки.
- Веб-smoke проходит после извлечения общей валидации в contracts.py.
- Отмена queued не запускает задачу; cancelling занимает слот до остановки.
- Нативный процесс и его дочерние процессы завершаются после EOF.
- Ошибка команды не ломает канал, переподключение не повторяет загрузки само.
- Команда с устаревшим session ID не применяется к задаче новой сессии.

Подробности текущих ошибок: [open-issues.md](open-issues.md).

## Этап 2. Проверить реальный сценарий расширения

### Работа

- Открыть расширение именно как sidePanel в отдельном тестовом профиле.
- Проверить регистрацию native-хоста и сквозную загрузку безопасного локального
  видео/файла. Не нужен платный или авторизованный источник.
- Пройти действия пользователя по таблице ниже. При обнаружении дефекта исправить
  его локально, добавить тест регрессии, повторить только затронутые проверки.
- Просмотреть скриншоты всех трёх разделов, двух тем и узкой панели 320 px.

| Сценарий | Ожидаемый результат |
|---|---|
| Нажать значок расширения | Открывается боковая панель; сайт остаётся доступен |
| Переключить вкладку/перейти по адресу | Заголовок и список относятся к текущей вкладке своего окна |
| Открыть второе окно браузера | Панели не путают вкладки, общая очередь сохраняется |
| Вставить HTTP(S)-ссылку | Одна подтверждённая задача, видимый прогресс и сохранённый файл |
| Скачать страницу | Команда использует source_kind=page, передаётся непосредственно в yt-dlp |
| Выбрать вариант master.m3u8 | Передаётся выбранный полный URL и его заголовки |
| Поймать тот же URL снова | Одна запись, актуальные заголовки/время наблюдения |
| Одинаковые имена в разных путях | Разные карточки с различимыми путями |
| Добавить больше задач, чем лимит | Лишние ждут; лимит не превышается |
| Отменить/повторить | Процесс останавливается; повтор создаёт новую задачу |
| Изменить настройки во время работы | Понятный отказ, текущие задачи не меняются |
| Изменить папку после завершения | Следующий файл в новой папке; старый доступен через Finder |
| Закрыть и открыть панель | Активные задачи и прогресс остаются |
| Закрыть браузер | Очередь и дочерние процессы останавливаются, частичные файлы удаляются |
| Нет помощника/yt-dlp/ffmpeg | Понятная диагностика и инструкция, без ложного статуса успеха |
| Ошибка 403/404/истёкшая ссылка | Ошибка видна; повтор не уничтожает уже готовые файлы |
| Очистить завершённые | Записи исчезают, файлы и активные задачи остаются |

### Критерий завершения

Хотя бы один настоящий файл проходит путь sidePanel → Native Messaging →
JobManager → файловая система. Проверены кликабельность, клавиатура, отсутствие
горизонтальной прокрутки и читаемость. Browser mock и настоящая ручная проверка
в отчёте явно различаются. Совместимость заявляется только для проверенных браузеров.

- Обновить README: боковая панель — основной сценарий; три раздела, Chrome API,
  установка/обновление, сохранение настроек, жизненный цикл задач, новые тесты.
- Обновить документацию native_host: одиночные команды совместимы; session v2

- Проверить diff, отсутствие локальных URLs/секретов/кэша и временных профилей в Git.
  `urls.txt` должен оставаться локальным ignored-файлом.
- Сохранить законченные изменения коммитом рабочей ветки. Отправку/слияние

**Готово, когда:** код, инструкция и реальное поведение совпадают; все P0 закрыты;
можно установить расширение по README и выполнить обычную загрузку из панели.

## Следующие улучшения: после завершения этапов 1–3

### 4. Понятный выбор качества и дорожек

**Цель:** до скачивания показывать название/обложку/длительность, варианты
качества и аудио. Не выводить качество только из имени файла или порядка списка.

**Реализация:** отдельный read-only запрос метаданных через yt-dlp; для HLS
различать master/media по содержимому. Запрос запускает пользователь, потому что
пойманная ссылка может быть временной/одноразовой. Выбор формата хранится в задаче,
прогресс анализа отделён от прогресса скачивания. Не менять параметры существующей задачи.

**Проверки:** master с несколькими вариантами, media без альтернатив, отдельные
video/audio, несколько языков, неизвестная длительность/live, таймаут анализа,
истёкшая ссылка, отсутствие ffmpeg. Выбранное качество и дорожка подтверждаются
метаданными выходного файла. Ошибка анализа не должна блокировать обычную загрузку.

### 5. История и настройки между перезапусками

**Цель:** видеть завершённые/ошибочные задачи после нового запуска браузера.

**Реализация:** определить минимальную схему и версию хранения. Не писать Cookies,
Authorization и подписанные CDN-ссылки в историю по умолчанию. Сохранять исходную
страницу, безопасные метаданные, путь и итог. Незавершённые после сбоя обозначать
как прерванные; автоматический перезапуск не делать без отдельного решения.

**Проверки:** перезапуск, повреждённая запись, миграция схемы, отсутствующий файл,
очистка истории без удаления файлов, отсутствие секретов в сохранённых данных.
Повтор со старой страницы должен получить актуальный адрес, когда источник это допускает.

### 6. Повысить совместимость на реальных источниках

**Цель:** проверенная матрица возможностей вместо обещания «скачает всё».

**Реализация:** небольшой набор разрешённых пользователю источников: прямой MP4,
HLS, DASH, страница с yt-dlp, iframe, поток с Referer/Cookie. Различать нехватку
зависимости, отказ сайта, истёкшую ссылку и отсутствие поддерживаемого извлекателя.

**Проверки:** собственные локальные фикстуры для регрессии и отдельные ручные
проверки выбранных сайтов; даты/версии инструментов записывать. Не включать внешние
сайты в обязательный стабильный offline-набор. Поддержку Windows/Linux и других
браузеров выделить в отдельную задачу: текущий установщик/Finder рассчитаны на macOS.

## Что пока не расширять

- Не объединять веб-очередь и extension-очередь новым фоновым сервисом без отдельного
  запроса: это меняет жизненный цикл и установку. Сейчас общий код, но разные экземпляры.
- Не добавлять полноценный desktop-клиент, облако, аккаунты или новый frontend-стек.
- Не считать скрытие похожих имён «универсальностью»: сохранять доступ к каждому адресу.
- Не вводить новые тестовые зависимости приложения ради разработки панели.

## Порядок работы для следующей модели

Читать HANDOFF → open-issues → затронутые файлы → воспроизвести конкретный сбой →
исправить → выполнить целевой тест → итоговые проверки → обновить документы.
Не перечитывать все исходники и не повторять исследование браузерных API без причины.

Справочные первоисточники по уже выбранной архитектуре:
[Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel),
[Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging).
