# Проверка этапов 1–3: боковая панель Viddow

Дата: 11 ноября 2026. Ветка: `feat/download-workspace`.
Текущая реализация сохранена и завершена локально, без новой платформы/daemon.
Основной интерфейс — sidePanel расширения. Веб-версия проверена как регрессия.

## Исправленные дефекты

- HTTP 413: тест отправлял большое тело в уже закрываемый сервером сокет и
  зависел от TCP-гонки. Проверка теперь отправляет завышенный Content-Length
  **без тела** и требует немедленный 413. Сервер по-прежнему не читает
  неограниченное тело; лимит 256 КиБ сохранён.
- Timeout смены вкладки: диагностика до/после клика показала правильную активную
  вкладку и искажённый русский title. Причина — отсутствие charset в HTML-фикстуре.
  Добавлен UTF-8; проверка смены вкладки сохранена. Дополнительно smoke переведён
  с обычной extension-вкладки на настоящий контейнер sidePanel.
- Повторное открытие панели: UI устанавливал «Подключаем…», но уже готовый порт
  не присылал новый ready. После connect UI повторно читает состояние подключения.
  Регрессия проверяется при открытии настоящей панели и её закрытии/открытии.
- Session ID проверялся только в worker. Теперь он передаётся с каждой командой
  и проверяется хостом до изменения очереди. Старые cancel/retry/clear/configure/
  download не затрагивают новую сессию, даже при совпадении ID задач.
- Ошибки запуска до ready сохраняются как offline; несовместимый протокол
  отвергается, преждевременные/чужие state не принимаются. Ошибка команды
  оставляет канал рабочим; reconnect не повторяет download.

## Настоящий сценарий расширения

Изолированный профиль получает регистрацию через
`install_native_host.py --user-data-dir <temporary-profile>`. В тесте хост
запускается через обёртку, записывающую PID, затем `exec native_host.sh` без
изменения Python-реализации. Порт и загрузчик не подменяются.

- MP4 сгенерирован локальным ffmpeg; ручная ссылка отправлена клавишей Enter.
  Файл из очереди совпал с исходным побайтово. Страница generic extractor yt-dlp
  тоже скачалась; результат совпал побайтово.
- HLS master с двумя query-вариантами: выбран точный URL с `token=one`; в
  запросе yt-dlp подтверждён свежий `X-Viddow: fresh`. Повторное наблюдение URL
  не увеличило список. Два пути `master.m3u8` — разные карточки. Выходной файл
  проверен ffprobe: видео 64×64.
- При лимите 1 дополнительная задача ждёт; отмена queued не отправляет HTTP-
  запрос. Прогресс виден. Отмена running останавливает передачу, повтор создаёт
  новую задачу. Временные файлы убраны. Изменение настроек при работе отвергнуто.
- Панель закрыта через sidePanel.close и открыта заново. Сессия, PID, ID задачи
  и её running-состояние сохранились. Отдельные страницы/навигация обновляют
  заголовок. Две настоящие панели в разных окнах показывают собственные вкладки
  и одну очередь/сессию.
- Новая папка и лимит применились после завершения задач. Следующий файл
  сохранён в новой папке. `reveal` старого файла из прежней папки успешно вызвал
  системный `open -R`. Визуальное выделение файла в Finder человеком не проверялось.
- 403/404 прямых файлов показаны как error. Очистка списка сохранила готовые
  файлы. Отсутствие yt-dlp/ffmpeg проверено Python-тестом с подменой поиска
  инструментов: понятная команда установки, без файлов и ложного done.
- После отключения реального хоста и временного удаления регистрации панель
  показала инструкцию установки. После возврата регистрации reconnect создал
  новую пустую сессию с сохранёнными настройками. Старая команда отвергнута.
- Закрытие браузера при работающем настоящем yt-dlp завершило хост и дочерний
  процесс; проверены записанные PID и отсутствие `.part` в папке загрузок.

Проверка выполняется автоматизацией видимого Chromium. Это **не ручной отчёт**
об установленном пользовательском браузере. Панель открывается настоящим
пользовательским жестом через sidePanel.open из временной extension-страницы,
после чего страница закрывается. Тип SIDE_PANEL и окно проверяются API.
`openPanelOnActionClick: true` проверен; физический клик по значку в toolbar
и совместимость пользовательского браузера остаются короткой ручной проверкой.

## Визуальная проверка

Просмотрены скриншоты потоков/задач и все три раздела в обеих темах на 320 px.
Проверены клики, Enter, читаемость, отсутствие горизонтальной прокрутки.
Последние снимки находятся в системном временном каталоге:
`viddow-extension-check/`, `viddow-native-check/`, `viddow-ui-check/`.
Их расположение можно задать переменной `VIDDOW_ARTIFACTS`.

Проверенный браузер: Google Chrome for Testing **156.0.8078.4** на macOS arm64.
Python **3.12**, Node.js **22.14.0**, yt-dlp **2026.10.21**, ffmpeg/ffprobe **8.0.1**.
Остальные Chromium-браузеры, авторизованные внешние сайты, Windows/Linux,
необычные права папок и очереди с суммарным снимком более 1 МиБ не проверены.
История сессионная; выбора качества/дорожек и восстановления после перезапуска нет.
