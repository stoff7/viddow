# Расширение — основной интерфейс Viddow

Пользовательский приоритет: управлять скачиванием из расширения. Веб-страница
остаётся дополнительным интерфейсом; основной сценарий не требует её запуска.

## Первый законченный сценарий

- Текущая вкладка: название, скачивание страницы, найденные потоки.
- Ручная вставка ссылки, общее управление задачами всех вкладок, отмена/повтор,
  очистка завершённых и показ файла в Finder.
- Настройки каталога и числа одновременных загрузок. Применяются при пустой
  активной очереди, сохраняются в локальном хранилище расширения.
- Светлая/тёмная тема и диагностика подключения локального загрузчика.
- Закрытие панели не прерывает задачи. Закрытие браузера/перезагрузка расширения
  закрывают Native Messaging и останавливают незавершённые загрузки.

## Ограничения и решения

1. Один постоянный Native Messaging-канал на расширение и один `JobManager`
   для всех его вкладок. Браузер запускает помощник автоматически. Веб-сервер
   не нужен. Очередь отдельно запущенного веб-сервера пока самостоятельна.
2. `JobManager` и ядро Python общие с веб-интерфейсом. Новый протокол сессии
   дополняет прежние одиночные команды: старое расширение остаётся совместимым.
3. Хост отвечает подтверждением на каждую команду и присылает снимки состояния.
   UI не объявляет загрузку начавшейся до ответа хоста. Отмена использует
   `cancelling`, слот освобождается только после реальной остановки.
4. Заголовки и токены загрузки остаются в памяти хоста/сессионном хранилище,
   не попадают в настройки. При разрыве связи UI показывает сохранённые задачи
   как прерванные; автоматического повтора скачиваний нет.
5. Одинаковый полный URL — одна запись с последними наблюдёнными заголовками.
   Для показа группируются только origin + полный pathname + тип потока.
   Разные query-параметры доступны как отдельные адреса внутри группы.
   Разные пути не объединяются только из-за совпадения имени `master.m3u8`.
6. Порядок сетевых ответов не определяет главный плейлист. Имя файла не
   доказывает качество/состав дорожек. UI не обещает «лучшее и все озвучки».
   Автоматического запроса пойманных ссылок ради классификации нет.
7. Список хранит последние 30 уникальных URL на вкладку, вытесняя старые;
   свежие адреса не отбрасываются при достижении лимита.

## Проверка

- Native-протокол: несколько задач в одной сессии, лимит, отмена, повтор,
  настройки, обрыв stdin и совместимость одиночных команд.
- JS: группировка, сохранение полных URL и заголовков, обновление одинакового
  URL, вытеснение старых записей, отображение ошибок подключения.
- Браузер: интерфейс расширения, смена вкладки, действия с задачами, настройки,
  темы; отдельный тестовый профиль, без изменения пользовательского профиля.

Фактический прогон 11 ноября 2026: [verification.md](verification.md). Реальный
путь sidePanel → зарегистрированный хост → файл проверен отдельно от mock-порта.

## Native Messaging session v2

Имя хоста — `local.video_downloader`. Фрейм: длина JSON в байтах (uint32
little-endian), затем UTF-8 JSON. stdout выделен протоколу, диагностика идёт в
stderr. Входящий фрейм хост ограничивает 1 МиБ; Chrome ограничивает сообщение
хоста 1 МиБ. Деления больших снимков на части пока нет; большие сессии с длинными
URL не входят в проверенную область применения.

Фоновый процесс расширения вызывает `connectNative` один раз и отправляет:

```json
{"type":"session","settings":{"workers":2,"output_dir":"~/Downloads"}}
```

Хост разворачивает путь и отвечает `ready` с `protocol: 2`, случайным `session`,
`jobs`, `settings` и `tools: {yt_dlp, ffmpeg}`. Пока ready нет, команды не
отправляются. Неверная версия протокола закрывает канал с видимой ошибкой;
таймаут ready — 10 с. Состояние чужой сессии или state до ready игнорируется.

Каждая команда содержит `request_id` (UUID от расширения) и актуальный `session`.
Хост проверяет session **до** изменения очереди; отсутствие/старый ID даёт
неуспешный reply. После reconnect ID задач могут снова начинаться с 1.

| Команда | Поля и результат |
| --- | --- |
| `download` | `urls` (1–50 HTTP(S)-ссылок), `name`, `page`, `referer`, `headers`, `source_kind` (`auto/page/direct`), опциональные `stream_kind` (`HLS/DASH`), `format_ids`; результат `{ids:[…]}`. Альтернатива: `analysis_id` + `format_ids` с исходным контекстом из анализа |
| `inspect` | Один URL и поля источника; немедленный результат `{analysis_id}`; метаданные приходят в `state.analysis` |
| `inspect_cancel` | `analysis_id`; отменяет только соответствующий текущий анализ |
| `cancel` | `id`; результат — снимок задачи. Повторная отмена допустима |
| `retry` | `id` задачи error/cancelled; результат `{id:…}` новой задачи с исходными параметрами |
| `clear` | Без дополнительных полей; удаляет done/error/cancelled, сохраняет файлы и активные задачи |
| `configure` | `settings: {workers, output_dir}`; 1–8 workers, абсолютный путь/`~`; только при отсутствии queued/running/cancelling. Результат — нормализованные настройки |
| `reveal` | `id` задачи done; запускает `open -R` только для существующего файла из результата этой задачи, включая прежнюю папку |

Ответ команды: `{type:"reply", request_id, ok:true, result}` или
`{type:"reply", request_id, ok:false, error}`. Ошибка команды не закрывает канал.
Reply подтверждает принятие команды, а не успешное завершение скачивания.
При таймауте reply (12 с) расширение предлагает проверить очередь до повтора:
автоматического повторения команд и гарантии exactly-once при потере ответа нет.

`state` содержит `session`, `jobs`, `settings`, `tools`, `analysis`; отправляется при изменении
снимка с периодом проверки 250 мс. Снимок задачи содержит `id`, полный `url`,
`name`, `status`, `fraction`, `label`, `path`, `error`, `format_ids`, `format_label`. Заголовки в снимки не
включаются. `cancelling` занимает слот до остановки исполнителя. В очереди не
более 200 незавершённых задач; завершённые записи очищает пользователь.

При EOF хост прекращает публикацию состояния, отменяет очередь и ожидает
завершения загрузчиков. Группы процессов yt-dlp/ffmpeg останавливает ядро;
частичные файлы удаляются. Закрытие UI не создаёт EOF: порт принадлежит worker.
После реального разрыва панель отмечает сохранённые активные задачи ошибочными.
Reconnect создаёт пустую новую сессию с сохранёнными настройками; задачи и
подписанные ссылки прежней сессии автоматически не повторяются.

## Совместимость одиночных команд

Первое сообщение `{type:"download", url, name, page, referer, headers}` выбирает
прежний режим: progress (`fraction`, `label`), затем done (`path`) или error
(`error`). EOF отменяет эту загрузку. Первое `{type:"reveal", path}` показывает
файл только из стандартной `~/Downloads` и возвращает `{type:"ok"}`. Для новых
настраиваемых папок применяется session v2 с `reveal` по ID задачи. Одиночные
команды не требуют session/request_id и остаются совместимыми со старым клиентом.
