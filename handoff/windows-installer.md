## Цель и ожидаемый результат следующей разработки

Получить локальный тестовый `Viddow-Setup-<version>-windows-x64.exe` (пример имени),
SHA-256, manifest версий компонентов, инструкцию установки/проверки/удаления и
отчёт о реально выполненных проверках. Версию назначать по готовности; v3.4.0
не заменять. Если executable не собран, не выдавать набор скриптов за установщик.

Пользователь не устанавливает Python, yt-dlp, ffmpeg, ffprobe и JS-runtime вручную;
не редактирует PATH/реестр и не запускает командную строку. Расширение устанавливает
отдельно в Chrome или Edge. Пакет полный, без загрузки исполняемых компонентов
из интернета при первом запуске. Для самого видео интернет, конечно, нужен.

## Что уже есть и чего не хватает

В ecb1292 есть Windows install/uninstall HKCU, фактический extension ID, binary
framing, .cmd launcher и isolated Job Object prototype. Resolver умеет комплектный
bin/. В f7d11e3 сохранены scheduler/retries/HTTP recovery; Windows persistence
сознательно отключён. Не включать persistence ради установщика без ACL-проверок.

До комплектного тестового выпуска нужно закрыть:
- рабочий Windows launcher с сохранёнными stdio и без лишних консольных окон;
- production-владение деревом yt-dlp/ffmpeg/ffprobe и его отмену/EOF;
- системную Downloads/Explorer, имена и доступ к папкам, logs/user data/temp;
- реальные install/connect/uninstall в Chrome/Edge и доступ к комплектным tools.
Технический .cmd с указателем на Python разработчика не удовлетворяет цели пакета.

## 1. Выбрать сборку и раскладку

Сделать короткий ADR: комплектный Python runtime + executable launcher либо
упакованный host. Для первого прототипа предпочесть обозримую folder-based
раскладку; single-file не обязателен. Конкретный упаковщик (например, PyInstaller)
и installer (например, Inno Setup/NSIS) — кандидаты, не принятые решения. Проверить
их официальные требования и лицензии перед выбором, не добавлять оба сразу.

Собирать Windows executable на доступной Windows-среде: VM/машина/CI, не обещать
обычную сборку Windows из macOS. В начале выяснить доступный способ запуска;
независимые build-скрипты/контракты можно готовить на macOS. Удалённый CI/push не
запускать без действующего разрешения. Если Windows исполнения нет, описать точный
блокер и воспроизводимые команды, не объявлять исполнимый пакет проверенным.

Пример логической структуры (имена уточняются ADR):
- user install root: launcher, versioned runtime/app, bin, native manifest, licenses;
- user data root: logs/config/cache; не писать их рядом с immutable executable;
- downloads: выбранная пользователем папка, не каталог установки.

Пути получать системно, а не подставлять имя пользователя. Проверить кириллицу,
пробелы, Unicode, quotes/percent там, где launcher раньше имел ограничения.
Упакованный host должен корректно находить bin независимо от cwd и __file__.

## 2. Комплектные зависимости и защита совместимости

Включить yt-dlp, ffmpeg, ffprobe, runtime host; дополнительные компоненты YouTube
(JS-runtime/EJS) и impersonation проверить на конкретных сборках. Версии/архитектура,
официальный источник, SHA-256 и лицензии фиксируются в manifest сборки.
Наличие имени yt-dlp.exe не доказывает поддержку Chrome impersonation.

Bundled-режим использует свои проверенные tools, а не системный PATH. Dev overrides
остаются отдельным режимом. yt-dlp получает свои ffmpeg location/runtime; state.tools
проверяет ту же раскладку, что использует запуск. Missing/corrupted binary — понятная
ошибка установки и repair, без тихого запуска случайной глобальной копии.
Бинарные зависимости — артефакты сборки, не случайные файлы в Git.

## 3. Launcher и процессы

Сохранить binary stdin/stdout Native Messaging, origin/browser args, ограничение
сообщений и диагностику вне stdout. Не использовать pythonw/GUI mode вслепую:
должны работать handshake, поток сообщений, EOF и native/session v2/history v1.
Окна console не должны мигать при каждом ffprobe/превью/скачивании.

Интегрировать Job Object только после Windows-проверки назначения до исполнения
дочернего кода, browser nested job, наследования handles и аварийного выхода host.
Потомок, переживший родителя, тоже завершается. Не убивать процессы глобально по
имени. Cleanup частей выполняется после остановки владельца, готовый файл сохраняется.

## 4. Мастер установки

Предлагаемые шаги: приветствие/назначение → выбор установленных Chrome/Edge →
связь с расширением → установка/проверка компонентов → готово и инструкция подключения.
Установка per-user, без обязательного администратора и изменения глобального PATH.

Для тестовой распакованной extension-сборки мастер принимает фактический ID
(32 символа a–p), объясняет, где его посмотреть; для двух браузеров допускает разные
ID. Публичную стабильную identity решить отдельно, не использовать macOS hash пути.
Не обещать «один клик» при ручном dev ID и не устанавливать расширение принудительно.

HKCU registration Chrome/Edge — существующий механизм с правильными views,
абсолютными путями, запретом замены чужого manifest. Установщик не обязан уметь
сам подтвердить браузерный handshake: проверка файлов/registry и реальное
«Подключено» в панели должны быть различимы. При частичной ошибке откатить свои
записи/файлы либо дать точное repair-состояние, не писать ложное «Готово».

Repair повторяет проверку и исправляет только свою установку. Uninstall снимает
только принадлежащие ей записи и компоненты. Видео/история расширения сохраняются;
удаление пользовательских данных — отдельный явный выбор, не default.

## 5. Обновление и доверие

Первый тестовый выпуск обновляется полным установщиком. Не заменять занятые
бинарники и не прерывать активную загрузку молча: попросить дождаться завершения
либо согласовать остановку. Сохранить рабочую версию до успешного переключения,
предусмотреть rollback. Independent yt-dlp update оставить последующим этапом.

Для публичного распространения определить code signing и доверенный канал.
При отсутствии сертификата тестовый пакет обозначить как неподписанный с честными
ограничениями; не обещать отсутствие SmartScreen и не отключать защиту Windows.
SHA-256 нужен для целостности, но не заменяет подпись/доверенное происхождение.
Лицензии выбранных runtime/ffmpeg/прочих компонентов включить в пакет по их условиям.

## 6. Приёмка перед передачей пользователю

Проверки — завершающим этапом законченной реализации. Чистая Windows 11 x64
без Python/yt-dlp/ffmpeg, Chrome и Edge; тестовый пользователь/VM для изоляции HKCU.
--user-data-dir сам по себе не изолирует registry. Личные cookies не использовать.

| Сценарий | Требуемый результат |
| --- | --- |
| Установка с нуля | Без терминала/PATH/admin-зависимости, свои компоненты найдены |
| Подключение в обоих браузерах | Настоящие ready/state/reply, нет загрязнения stdout |
| Прямой MP4 и HLS | Правильное видео, корректная длительность и звук |
| Раздельные дорожки | ffprobe подтверждает video+audio в итоговом файле |
| Отмена/закрытие браузера | Нет дочерних процессов/занятых частей, очередь освобождена |
| Перезапуск | История есть, самопроизвольной загрузки нет |
| Показать файл | Explorer выделяет настоящий файл по клику |
| Кириллица/пробелы/Downloads перенесена | Пути и имена корректны |
| Нет прав/места/повреждённый tool | Понятная ошибка, нет потери готовых файлов |
| Повтор install/repair/update/uninstall | Чужая регистрация и видео не затронуты |

Проверять именно собранный installer, не только Python-код. Отдельно фиксировать
непроверенные внешний CDN, browser cookies, сетевой/внешний диск и Windows resume.
MacOS regression затронутых общих функций нужна, новая macOS-упаковка не prerequisite.

## 7. Инструкция для пользователя, которую подготовить вместе с пакетом

1. Скачать installer и сверить опубликованный SHA-256 при необходимости.
2. Установить расширение; для dev-сборки скопировать ID из страницы расширений.
3. Запустить installer, выбрать браузер и ID. Не ставить дополнительные инструменты.
4. Открыть панель, нажать проверку подключения, скачать короткое тестовое видео.
5. Проверить звук, отмену отдельной загрузки и «Показать файл».
6. Если сбой — открыть встроенную диагностику/папку логов по явному действию;
   предоставить обезличенный журнал и версию пакета, без cookies/подписанных URL.
7. Описать repair и удаление через обычный механизм Windows.
