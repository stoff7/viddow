# Одна карточка для ошибок одной попытки загрузки

12 ноября 2026. Пользователь просит не размножать карточки ошибочных загрузок
одного видео: повторные ошибки должны находиться внутри одной карточки.

- JobManager выдаёт непрозрачный attempt_id. Явный «Повторить» наследует его.
  Повторная отправка того же полного URL после ошибки также наследует ID, только
  если совпадают все параметры, включая выбранные форматы и приватные заголовки.
  Другая серия/query, дорожка, заголовки или качество не объединяются по имени/CDN.
- Новые успешные и параллельные скачивания самостоятельны. Несколько сохранённых
  файлов не исчезают из списка. Реальные задания очереди не удаляются/не меняются.
- UI скрывает повторные error-строки одной семьи, показывает последнее задание
  и сворачиваемые «Ошибки попытки» с количеством, временем и причинами. Если повтор
  уже выполняется или завершился, предыдущие ошибки находятся в его карточке.
  Счётчик соответствует числу карточек; прогресс/отмена относятся к реальному job.
- История v1 сохраняет только необязательный UUID attempt_id, без исходных URL и
  заголовков. После перезапуска связь повторов остаётся. Старые записи без ID не
  объединяются по урезанному origin/странице: соответствие видео для них недоказано.
- Сквозной журнал получает attempt_tag, чтобы находить цепочку по одному ID.
  Проверки выполняются в конце: модель группировки, параметры повторов, история
  и одна UI-проверка карточки с несколькими ошибками.

Проверено завершающим этапом: 11 JS-тестов модели/истории и 20 Python-тестов
очереди/истории/native-протокола/журнала прошли. Настоящий native smoke создал три
HTTP 404 одной попытки (job 5/6/7, один attempt_id): UI показывает одну error-карточку
и три записи внутри details. Счётчик — 5 карточек вместо 7 заданий: четыре готовых
файла и одна попытка с ошибками. Снимок просмотрен:
`/tmp/viddow-auto-native/one-attempt-errors.png`. Журнал этого прогона прочитан:
три job_error имеют общий attempt_tag. Секреты запроса в историю не добавлены.
