# Стабильная панель и работающий плеер

12 ноября 2026. Пользователь сообщил о рывках панели и любого воспроизводимого
плеера, затем о повторяющихся Extension context invalidated и ошибках API/null.
В этот этап пользователь явно запретил запуск тестов.

По чтению кода: MutationObserver реагировал на class/style всего документа,
отправлял немедленное и отложенное уведомление, панель очищала изображения,
перезапускала allFrames и кодировала до 24 JPEG без кеша. Параллельные запросы
не отменялись при получении нового запроса. Отдельно старый content script
вызывал sendMessage вне try: синхронная ошибка контекста не ловилась .catch.

## Инварианты правки

- События coalesce, один обход панели одновременно, без таймера опроса.
- Кадр кешируется по generation/размеру/готовности media, включая отказ CORS;
  новый media/poster и готовность к декодированию обновляют свидетельства.
- Изображение сохраняется при обновлении того же источника; другой источник
  по-прежнему проверяется по ключам документа/media. Выбор и очередь не теряются.
- Мутации контролов/счётчиков/субтитров без media не запускают обход плееров.
- После потери extension context content script отключает observers/listeners;
  bootstrap не порождает рекурсивную ошибку диагностики. Исчезнувшая вкладка
  не создаёт необработанное исключение.
- Результат проверяется чтением diff. Тесты, браузерные воспроизведения и
  проверки синтаксиса в этом этапе не запускаются по просьбе пользователя.

Modern Web Guidance: performance, «DO debounce or throttle rapid event listeners».
efficient-background-processing просмотрен для оценки подхода; CSS content-visibility
и фоновые симуляции здесь не добавлялись.

## Изменения

page-preview.js фильтрует мутации по наличию media и объединяет уведомления в
одно за 250 мс. Кадр и отказ его получить кешируются в WeakMap; смена media
generation или размеров позволяет получить новый кадр. Стили общих предков
читаются один раз в рамках снимка, не отдельно для каждого video.

Панель допускает один снимок одновременно, старты не чаще раза в 300 мс;
поступившие в это время запросы объединяются. Для невидимой панели новый обход
не запускается. Начальное окно кадров уменьшено с 24 до 6, выбранный плеер
включается отдельно. Неизменный src картинки не присваивается повторно.
Обычное уведомление не очищает превью, реальная смена вкладки очищает его.
VideoPreparation не публикует одинаковый снимок повторно.

Синхронная ошибка sendMessage теперь ловится вместе с отказом Promise. После
потери контекста content script отключает observers и DOM/message listeners.
Bootstrap не выбрасывает ошибку из отправки диагностики и не повторяет
обработку первой ошибки рекурсивно. Панель прекращает снимки при исчезновении
API; nullable window/tab/analysis обработаны в затронутых переходах, ошибка
badge для уже закрытой вкладки не становится необработанным исключением.

## Состояние проверки

Выполнено только чтение кода, свежего журнала и diff. В свежем файловом журнале
panel_error отсутствовал; перечисленные browser errors предоставлены пользователем.
Причины нагрузки найдены по обработчикам, количественное снижение CPU/рывков
не измерялось. Новые правки не проверены исполнением по прямому запрету тестов.
Нужна перезагрузка расширения и самой страницы видео: уже внедрённый старый
скрипт нельзя исправить простым изменением файла в репозитории.
