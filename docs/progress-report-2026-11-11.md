# Viddow: отчёт о текущем состоянии

11 ноября 2026. Основной интерфейс — боковая панель расширения.

## Что сделано

Этапы 1–3: постоянная панель, список потоков текущей вкладки, одна очередь
всех вкладок/окон расширения, управление через Native Messaging без ручного
запуска сервера. Добавлены отмена, повтор, настройки папки и параллелизма,
корректное завершение дочерних процессов. Веб-интерфейс и CLI сохранены.

Этап 4: явный анализ страницы/потока, выбор качества и аудиодорожек,
проверка принадлежности форматов текущему анализу и наличие ffmpeg для сборки.
Поддержан выбор нескольких звуковых дорожек для video-only.

Этап 5: безопасная постоянная история с версионированием. В ней нет сырых
CDN-ссылок, cookies, заголовков авторизации и старых format IDs. После
перезапуска незавершённые задачи отмечаются прерванными, автоматически не
запускаются. Повтор со страницы получает новые форматы и требует подтверждения.
Очистка истории сохраняет скачанные файлы.

В рамках этапа 6:

- Добавлен явный выбор сеанса браузера для YouTube, включая Vivaldi. Выбор
  применяется к анализу и загрузкам YouTube через штатный механизм yt-dlp;
  cookies не экспортируются в файл и не возвращаются в историю/интерфейс.
- Исправлена смена сеанса: готовый анализ сбрасывается, текущий отменяется,
  старый выбор формата отвергается во всех панелях. Новый анализ получает
  актуальную настройку; параметры созданных задач не меняются.
- До первых байтов показывается время подготовки. Повторы ограничены;
  отсутствующие фрагменты не пропускаются ради ложного успешного результата.
- Добавлена кнопка «Обновить ссылку»: новый анализ исходной страницы вместо
  повтора того же CDN URL. На вкладке YouTube доступна и у найденного потока;
  у ошибочной/отменённой задачи — если известна исходная страница.
- Причины ошибок разделены: вход, отказ HTTP, истёкшая ссылка, таймаут,
  TLS, зависимости, DRM, папка. Сырые детали доступны в текущей сессии.
- При TLS `curl (35)` до начала вывода добавлена одна попытка без явно
  принудительной имитации Chrome. Проверка сертификатов сохранена.
- Исправлено оформление метаданных macOS через публичный URL API после
  сохранения файла. Карантин не удаляется; содержимое не меняется.
  Тот же подход применён к указанному пользователем уже скачанному MP4.

## Подтверждённые результаты и границы

В ходе этапов 1–5 прошли 42 Python-теста, 13 JS-тестов и три браузерных smoke.
Проверялся настоящий sidePanel → Native Messaging → файл, локальные MP4/HLS,
выбранное качество и два языка через ffprobe, очередь, отмена и история
после реального перезапуска тестового браузерного профиля.

До последнего запрета частых полных прогонов проверялись изменения сеанса
YouTube и метаданных macOS. Для последней TLS-правки прошли только два
точечных теста. Кнопка обновления требует дальнейшей ручной проверки.
Полный набор после последних правок не запускался. Автотесты не читают
личные cookies и не открывают Finder по умолчанию.

После исправления смены сеанса прошли 21 тест `test_source_auth` и
`test_inspector` и два TLS fallback-теста; оба новых регрессионных теста
воспроизвели дефект до исправления. Прошли синтаксические проверки
`extension/popup.js`, обоих изменённых браузерных smoke-скриптов и
`git diff --check`. Это точечная проверка без браузера и личных cookies.

Пользовательская проверка в Vivaldi, по присланному списку:

| Наблюдение | Что можно заключить |

Гипотеза пользователя: обрыв может совпадать со сменой сервера VPN.
Она сохранена как неподтверждённая в [stream-tls.md](stream-tls.md).
Вывод о вредоносности MP4, истечении ссылки или виновности VPN не делается.

## Что остаётся

Этап 6 **не завершён**. Нет подтверждённой внешней матрицы X/VK/AnimeGo;
yummyanime.tv и userplay.live не подменяют проверку AnimeGo.
Остаются лимит Native Messaging 1 МиБ, устаревшие ответы после SPA/навигации,
защита от дублирования команды после потери reply, дополнительные дорожки
для combined-форматов и проверка нестандартных условий папки/диска.
Нет восстановления частичной загрузки между задачами/перезапусками.
Постоянная проверка работоспособности подписанных ссылок не реализована.

У generic-формата метаданные могут содержать только ID `0`, без сведений о
дорожках. Надпись «состав дорожек неизвестен» означает отсутствие метаданных,
а не отсутствие звука. Улучшение этой подписи остаётся задачей интерфейса.

Мобильная версия отложена. Другие ОС не проверены. Текущие изменения этапа 6
сохраняются локальным коммитом вместе с исправлением смены сеанса;
push/merge не выполнялись. Актуальное состояние Git — в [handoff](../handoff/HANDOFF.md).
Этапы 1–3: `5f748f4`, этап 4: `1f96624`, этап 5: `8d80fd0`.

## Оценка и следующий приоритет

Основной путь уже пригоден для ручной работы: панель управляет очередью,
есть успешные загрузки с реальных источников, ошибки показывают причины.
Однако единичный успех не подтверждает стабильность всего источника.
Самая заметная практическая слабость сейчас — потеря прогресса при обрыве сети.

Следующим приоритетом считаю отдельный контракт восстановления: ограниченные
повторы временных ошибок в одной задаче, удержание промежуточных данных на
оговорённый срок и продолжение только при подтверждении того же источника,
формата и набора дорожек. Простая подстановка свежей ссылки в частичный файл
может смешать разные версии медиа, поэтому такое поведение нельзя добавлять
без проверки соответствия. Это предложение, ещё не реализованная функция.

Сначала полезно сопоставить обрыв с переключением VPN вручную; затем исправлять
воспроизведённый сценарий, сохраняя работающий путь загрузки. Полные прогоны
во время активной ручной проверки не запускать без запроса пользователя.
