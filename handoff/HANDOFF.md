## Состояние приложения

- Общая боковая панель Chromium, компактные карточки видео с качеством/аудио,
  прогрессом и результатом; native-host, очередь всех вкладок/окон, история.
- Выбранный плеер, автоматическая подготовка HLS/DASH, GIF, раннее намерение
  скачать, восстановление после ошибок страницы, группировка ошибок попытки.
- Подтверждение отдельных HLS-дорожек через ffprobe и объединение X video/audio.
- Web/CLI сохранены; веб-очередь отдельная. Не вводить daemon ради Windows.
- README описывает архив с Python-кодом; yt-dlp и ffmpeg ставятся отдельно.
  Удобный Windows-установщик с инструментами пока только предложение.

## Что уже обнаружено для Windows

- install_native_host.py использует ~/Library/Application Support, chmod и
  native_host.sh; текущая установка ориентирована на macOS.
- native_session.py вызывает open -R; DEFAULT_DIR в download.py — ~/Downloads.
- download.py использует POSIX process group для отмены; ветку Windows и всех
  потомков требуется отдельно проверить/реализовать, не считать перенос готовым.
- Поиск инструментов через shutil.which используется в нескольких модулях.
- Различия ОС вынести в минимальный общий адаптер; интерфейс и бизнес-логику
  очереди/анализа сохранять общими. Точные Windows API/ключи проверить перед кодом.

## Следующие действия

1. Аудит всех ОС-зависимых мест и контракт платформенного адаптера.
2. Рабочий Windows native-host + регистрация для Chrome/Edge; сначала
   техническая установка, затем упаковка для пользователя без настройки PATH.
3. Папка Downloads, Explorer, безопасные имена и полная отмена дерева процессов.
4. Сквозная проверка на настоящей Windows: установка → видео+звук → отмена →
   повтор/история → показ файла, кириллица и пробелы в путях.
5. После доказанного рабочего пути — установщик, обновление/удаление,
   отдельный Windows-артефакт и документация. Поддержку не объявлять по mock-тестам.
