# UX боковой панели: результаты и направление следующей сессии

11 ноября 2026. Пользователю интерфейс кажется неинтуитивным. После ревью
пользователь согласился сохранить предложенное направление для новой сессии.
Это план, а не реализованный дизайн; конкретный макет ещё не утверждался.

## Наблюдения

Главная проблема: интерфейс требует выбрать способ скачивания прежде, чем
понятно, какое видео и в каком виде получится.

- На первом экране конкурируют скачивание страницы, отдельная ссылка качества,
  ручной URL и список потоков с собственными кнопками скачивания/качества.
- master.m3u8, index-f1-v1-a1.m3u8, CDN, пути и время обнаружения заставляют
  выбирать технический адрес вместо понятного видео.
- «Качество и звук на странице» — маленькая ссылка вне карточки страницы;
  важная часть сценария выглядит второстепенной. Результат анализа появляется
  ниже формы ручной ссылки, а не внутри карточки выбранного источника.
- «Повторить» и «Обновить ссылку» требуют понимания причины сбоя и разницы
  между старым CDN URL и новым анализом исходной страницы.
- Большая шапка, уведомления и постоянные пояснения отнимают место в узкой панели.
  Многие подписи и действия имеют размер 9–11 CSS px.
- Настройки показывают инструкции установки даже при работающем помощнике.
- После каждого запуска происходит автоматический переход в «Загрузки»;
  это прерывает подбор других видео на странице.

## Предложенный основной сценарий

1. Карточка текущего видео/страницы: понятное название и сайт; обложка только
   когда она доступна. Не выдавать название вкладки за подтверждённое видео.
2. Главное действие «Подготовить скачивание» получает доступные варианты.
3. В той же карточке — качество, озвучка, одна кнопка «Скачать».
   Подходящий вариант выбран заранее, если метаданные позволяют. Не выбирать
   молча немое видео и не обещать все дорожки при неизвестном составе.
4. После запуска показать прогресс в карточке и доступ к общей очереди;
   не переключать раздел принудительно после каждого добавления.

Прямые файлы и источники без метаданных должны сохранять доступный путь
скачивания. Не делать успешный анализ обязательным для всех типов источников.

## Перехваченные потоки и дополнительные действия

- Сохранить полноценный запасной путь «Видео не найдено? Выбрать найденный поток».
  На сайтах, где анализ страницы не работает, он должен оставаться заметным.
- При отсутствии метаданных допустимо «Поток 1 · качество неизвестно»;
  рядом дать достаточно различий для выбора. Полные адреса, варианты query,
  время обнаружения и технические параметры раскрывать в деталях.
- Не объединять разные адреса в одно видео без подтверждения соответствия.
  Не считать первый поток или файл master гарантией лучшего качества/всех озвучек.
- Ручную ссылку оставить доступной как отдельное вторичное действие.
- Для ошибок показывать понятный следующий шаг по причине, технические детали
  раскрывать отдельно. Не менять молча смысл retry/обновления страницы.

## Визуальное направление

Сохранить текущую палитру. Сделать компактнее шапку, увеличить мелкие подписи
и текстовые кнопки, сократить постоянные служебные пояснения. На карточке одно
главное действие. Инструкции установки показывать при проблеме или в раскрываемой
диагностике. Одна перекраска без изменения сценария не решит проблему.

## Границы и критерии проверки

- Сначала переработать главный экран и выбор качества; не переписывать backend,
  историю, протокол Native Messaging или добавлять daemon ради внешнего вида.
- До анализа понятно, что будет сделано; после анализа ясно, какое видео,
  качество и звук выбраны. Скачивание требует явного действия пользователя.
- Новый пользователь не обязан знать HLS, CDN, master/media для основного пути.
- Поток без метаданных и прямая ссылка по-прежнему скачиваются.
- Подготовка, пустой результат, ошибка, отмена и отключение помощника имеют
  понятные состояния; отключённая кнопка сопровождается причиной.
- Смена вкладки/сеанса и поздний анализ не подменяют выбранный источник.
- Общая очередь, отмена, повтор и история доступны без потери настроек выбора.
- Проверить 320–400 px, обе темы, длинные названия, клавиатурный фокус и прокрутку.
- Использовать точечные тесты изменённых сценариев; полный прогон только по запросу.

Визуально просмотрены streams, jobs, settings. Скриншоты временные:
`/tmp/viddow-ux-review/extension-streams.png`, `extension-jobs.png`,
`extension-settings-dark.png`. Снимок streams имеет артефакт полноэкранной
склейки в нижней части — не считать повтор шапки дефектом продукта.
Выбор качества изучен по HTML/JS, не проверен отдельным визуальным сценарием.
Реальные загрузки и пользовательские cookies не использовались. Код не изменён.
