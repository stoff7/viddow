# Viddow

Локальный загрузчик видео на Python. Основной интерфейс — постоянная боковая панель расширения Chromium; веб-страница и CLI доступны дополнительно.

## Возможности

- Скачивание прямых ссылок на файлы средствами стандартной библиотеки Python.
- Загрузка HLS/DASH-потоков через `yt-dlp` или, если его нет, `ffmpeg`.
- Загрузка страниц с видео через `yt-dlp`, если он поддерживает источник.
- Анализ по запросу: название, обложка/длительность при наличии, выбор разрешения и звуковых дорожек.
- Поиск ссылок на видео в HTML: по адресу страницы, из вставленного кода или файла.
- Перехват HLS/DASH-запросов вкладки расширением и передача заголовков запроса загрузчику.
- Веб-интерфейс со светлой/тёмной темой и адаптацией для телефона.
- Общая очередь всех вкладок расширения: лимит, отмена, повтор, фильтры и очистка завершённых.
- Папка сохранения, параллелизм и тема в настройках панели.
- Прогресс загрузки и подбор свободного имени файла; в расширении — отмена и показ файла в Finder.

По умолчанию файлы сохраняются в `~/Downloads`.

## Требования

- Python 3.9 или новее.
- Для страниц с видео — `yt-dlp`.
- Для объединения отдельных видео- и аудиодорожек — `ffmpeg`; он также используется как запасной загрузчик потоков.

Установка инструментов на macOS через Homebrew:

```sh
brew install python yt-dlp ffmpeg
```

Расширение запускает инструменты через `PATH`, включающий стандартные каталоги Homebrew. В режиме перехваченного потока загрузчик использует `yt-dlp --impersonate chrome`: установленная сборка yt-dlp должна поддерживать этот режим.

## Боковая панель расширения на macOS

1. Откройте управление расширениями браузера, например `chrome://extensions`.
2. Включите режим разработчика и загрузите распакованное расширение из папки `extension`.
3. В терминале из папки проекта выполните `python3 install_native_host.py`.
4. Обновите расширение кнопкой ⟳ на странице управления расширениями. Закрепите его значок на панели браузера.
5. Откройте страницу с видео и нажмите значок Viddow: боковая панель остаётся рядом с сайтом. Запускать `server.py` не нужно.

В панели три раздела:

- **На странице**: текущая вкладка своего окна, кнопка «Скачать видео со страницы», ручная HTTP(S)-ссылка и найденные HLS/DASH-потоки. Для обнаружения потока запустите видео в плеере. Можно раскрыть карточку и выбрать полный адрес с нужными параметрами; одинаковые имена в разных путях остаются отдельными карточками. Название плейлиста не гарантирует качество или наличие всех дорожек.
- **Загрузки**: одна очередь всех вкладок и окон расширения, прогресс, отмена, повтор ошибки/отмены, фильтры, очистка записей и «В Finder». Повтор создаёт новую задачу; очистка сохраняет файлы. Добавление считается успешным после ответа помощника.
- **Настройки**: полный путь папки (допускается `~/Downloads`) и 1–8 одновременных загрузок. Изменения применяются, когда нет активных/ожидающих задач. Тема, папка и лимит сохраняются между запусками браузера в локальном хранилище расширения. Файлы из прежней папки остаются доступны через Finder.

Чтобы выбрать качество, нажмите **«Качество и звук»** у найденного потока, для текущей страницы или для вставленной ссылки. Анализ делает запросы к источнику, но не начинает скачивание. Выберите видео и нужные языки, затем «Скачать выбранное». Несколько отдельных аудиодорожек требуют ffmpeg; для видео без звука есть явный выбор. Уже встроенный звук показывается отдельно, неизвестный состав обозначается прямо. Доступные качества определяет источник; имя `master.m3u8` само по себе ничего не гарантирует.

Анализ можно отменить; его таймаут — 30 секунд. Пока он идёт, обычные загрузки и их отмена доступны. Ошибка анализа не мешает скачать обычной кнопкой. Анализ общий для панелей текущей сессии; новый анализ заменяет предыдущий. Выбор и исходные заголовки копируются в задачу, поэтому смена вкладки не подменяет ссылку. Повтор сохраняет выбранные форматы; если они исчезли или ссылка истекла, запросите качество заново. Подробнее: [этап 4 и проверки](docs/quality-selection.md).

Закрытие панели сохраняет очередь и Native Messaging-канал в фоновом процессе расширения. Закрытие браузера или перезагрузка расширения останавливают незавершённые задачи и дочерние процессы; частичные файлы удаляются, готовые сохраняются. История сессионная: после нового запуска браузера список пуст, автоматического повтора нет. При разрыве связи панель показывает ошибку и кнопку «Подключить»; задачи прежней сессии не отправляются заново.

Для работы нужны [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) и [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging). Манифест требует Chrome API 116+. Разрешения: `sidePanel`, `nativeMessaging`, `storage`, `webRequest` и доступ к HTTP(S)-источникам через `<all_urls>`. Полные адреса и заголовки сохраняются в памяти/сессионном хранилище для текущей загрузки, а в постоянные настройки не записываются.

Установщик регистрирует хост в найденных каталогах Chrome, Chromium, Vivaldi, Brave, Edge и Яндекс Браузера. **Реальный сквозной сценарий проверен на macOS с Google Chrome for Testing 156.0.8078.4**; остальные браузеры требуют отдельной проверки поддержки sidePanel. После перемещения проекта загрузите расширение заново и повторите установку хоста: регистрация и ID зависят от пути.

При обновлении кода обновите распакованное расширение. Перерегистрировать хост при прежнем пути не требуется: он запускает Python из этой папки. Если помощник не найден, повторите установку и нажмите «Подключить». Наличие yt-dlp/ffmpeg показано в настройках; сообщения ошибок содержат команду установки.

Для изолированной проверки предусмотрена регистрация только в заданном каталоге данных браузера (без записи в пользовательские профили):

```sh
python3 install_native_host.py --user-data-dir /tmp/viddow-test-profile
```

Этот браузер должен запускаться с тем же `--user-data-dir`. Протокол и границы очереди описаны в [docs/extension-control.md](docs/extension-control.md), результаты — в [docs/verification.md](docs/verification.md).

## Веб-интерфейс

Из папки проекта:

```sh
python3 server.py
```

Откроется `http://127.0.0.1:8765/`. Вставьте ссылку на страницу с видео, файл или поток и нажмите «Скачать». Задача появится в списке; одновременно выполняются две загрузки, остальные ждут очереди.

В «Параметрах загрузки» можно задать имя и тип ссылки. Режим «Страница с видео» сразу передаёт адрес в yt-dlp, обходя предварительный запрос urllib. В автоматическом режиме ошибки HTTP 401/403/405/429 для предполагаемой страницы также дают возможность попробовать yt-dlp.

В списке можно отменить задачу, повторить ошибочную/отменённую загрузку и скопировать путь готового файла. Очистка списка сохраняет файлы на диске. При потере связи интерфейс показывает сообщение и автоматически восстанавливает опрос.

«Поиск в HTML» открывает дополнительный инструмент: загрузка исходного кода по адресу, вставка HTML или перетаскивание файла, выбор найденных ссылок, копирование ссылок и команды для CLI.

Другой порт и запуск без открытия браузера:

```sh
python3 server.py --port 8766 --no-browser
python3 server.py --workers 3 -o ./downloads
```

Сервер слушает только `127.0.0.1`. Параметр `--workers` принимает значения от 1 до 8. При открытии `video-links.html` как локального файла доступен разбор HTML, но скачивание через сервер недоступно. Для такого запуска рядом с HTML должна оставаться папка `web`.

## CLI

```sh
python3 download.py 'https://example.com/video.mp4'
python3 download.py 'https://example.com/watch/123' -n 'Моё видео'
python3 download.py 'https://example.com/watch/123' --source-kind page
python3 download.py 'https://example.com/master.m3u8' --referer 'https://example.com/watch/123'
python3 download.py 'https://example.com/video.mp4' -o ./downloads
python3 download.py --help
```

Можно передать несколько адресов: CLI обработает их последовательно.

## Структура

| Файл | Назначение |
| --- | --- |
| `download.py` | Выбор способа скачивания, имена файлов, прогресс и CLI |
| `server.py` | Локальный HTTP-сервер и проверка запросов |
| `jobs.py` | Очередь, состояния задач и управление отменой |
| `video-links.html`, `web/` | Веб-интерфейс и извлечение ссылок из HTML |
| `extension/` | Расширение Chromium: перехват потоков и управление загрузками |
| `native_host.py`, `native_host.sh`, `native_session.py` | Native Messaging: одиночные команды и session v2 |
| `contracts.py` | Общая валидация запросов HTTP/Native Messaging |
| `inspector.py` | Отдельный анализ метаданных и проверка выбранных форматов |
| `install_native_host.py` | Регистрация хоста в браузерах на macOS |
| `tests/` | Автотесты ядра, очереди, HTTP и браузерных сценариев |
| `docs/first-improvements.md` | Решения, HTTP-контракт и критерии приёмки |

## Проверка

Тесты Python используют стандартную библиотеку, временные каталоги и HTTP-серверы на loopback. Пользовательская папка загрузок не затрагивается, внешние сайты не запрашиваются:

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_streams.mjs tests/test_formats.mjs
```

Браузерный тест дополнительно требует Node.js, Playwright и Chromium. Playwright можно установить отдельно от проекта, например во временную папку:

```sh
npm install --prefix /tmp/viddow-browser-check --no-package-lock playwright
/tmp/viddow-browser-check/node_modules/.bin/playwright install chromium
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/extension_smoke.cjs
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/extension_native_smoke.cjs
NODE_PATH=/tmp/viddow-browser-check/node_modules node tests/browser_smoke.cjs
```

`extension_smoke.cjs` проверяет настоящую боковую панель и webRequest с подменённым native-портом: команды, смену вкладки, темы, 320 px, ошибки до ready, таймаут и reconnect без повторов. `extension_native_smoke.cjs` использует настоящий зарегистрированный хост и локальное видео: MP4, страницу/HLS через yt-dlp, очередь, выбор качества/двух языков с ffprobe, два окна, закрытие/открытие панели, смену папки, ошибки, reconnect и остановку хоста/yt-dlp после закрытия браузера. Нужны yt-dlp, ffmpeg и ffprobe; расширение проверяется в видимом окне современного тестового Chromium. Скрипт устанавливает хост исключительно во временный профиль и удаляет профиль/файлы после проверки. Окна Finder по умолчанию не открываются: реальный `reveal` включается только явным `VIDDOW_TEST_FINDER=1`; обычный Python-тест проверяет его с подменой системного вызова.

`browser_smoke.cjs` проверяет дополнительный веб-интерфейс: скачивание, отмену, повтор, HTML-поиск, восстановление связи и адаптивность. Скриншоты находятся в `viddow-extension-check`, `viddow-native-check` и `viddow-ui-check` внутри системного временного каталога. Для уже установленного Chromium можно передать путь к исполняемому файлу через `CHROMIUM_PATH`; каталог скриншотов меняется через `VIDDOW_ARTIFACTS`.

## Текущие ограничения

- Разбор HTML не выполняет JavaScript страницы; динамические потоки может обнаружить расширение при воспроизведении видео.
- Поддержка источника зависит от сайта, авторизации и возможностей установленной версии yt-dlp; скачивание любого видео не гарантируется.
- Очередь веб-сервера и очередь расширения независимы. `--workers` относится к веб-серверу, настройка панели — к расширению.
- Отмена сетевого чтения может ждать до таймаута (30 с); в это время задача отмечена как останавливающаяся. На POSIX отмена внешнего инструмента останавливает также его дочерние процессы.
- История загрузок не сохраняется между перезапусками сервера или браузера, возобновление прерванных задач не реализовано.
- Плейлисты отключены: загрузчик передаёт yt-dlp параметр `--no-playlist`.
- Установщик расширения и показ файла в Finder рассчитаны на macOS.
- Большие сессии с очень длинными URL упираются в лимит Native Messaging 1 МиБ на сообщение хоста. Разбиение снимков очереди на части пока не реализовано; поддержку таких очередей не заявляем.
