# Аудит Viddow — 14 ноября 2026

База: `71f18b5`, ветка `build/windows-installer-test`. Прочитаны handoff,
основные модули загрузчика, очереди, Native Messaging, расширения, документы
и тесты. Это выборочный инженерный и продуктовый аудит, не полный security
review и не приёмка установленного Windows-пакета. Код приложения не изменён.

## Решение, предлагаемое владельцу

Остановить расширение функций. Провести ограниченную стабилизацию, затем
использовать программу 1–2 недели. Новые задачи брать только из повторяющихся
проблем реального использования. Это рекомендация, а не уже принятое решение.

Для личного инструмента функциональности достаточно: обнаружение видео,
качество/озвучки, очередь, отмена, история, повтор, показ файла, диагностика.
Главная незакрытая потребность — предсказуемость всего пути от установки до
готового правильного файла. Для публичного продукта готовность пока не доказана.

## Подтверждённые находки

### 1. Высокий приоритет: история теряет Windows-пути

`extension/history-model.mjs:31` принимает путь только с начальным `/`.
Вызов реальной `historyFromJobs()` с завершённой задачей воспроизвёл:

| Вход | Сохранённое значение |
| --- | --- |
| `C:\Users\Test\Downloads\video.mp4` | `null` |
| `\\server\share\video.mp4` | `null` |
| `/Users/Test/Downloads/video.mp4` | исходный путь |

Файл не удаляется, но после восстановления истории теряется возможность
показать его через сохранённую запись. Наличие рабочего Explorer reveal в
Python не исправляет потерю данных на стороне расширения.

Нужно: согласованная проверка абсолютных POSIX/Windows/UNC-путей и регрессия
save → decode → восстановление → reveal. Относительные пути и управляющие
символы по-прежнему отвергать; поддержку UNC подтвердить на реальной Windows.

### 2. Высокий приоритет: проверки интерфейса отстали от реализации

`tests/extension_smoke.cjs:140` ожидает `#pageThumbnail`, далее `#pageFacts`,
`#analysisStatus`, `#analysisResult`; текущая панель использует карточки и этих
элементов не создаёт. Это подтверждает предупреждение README о старых smoke.
Браузерный прогон в этом аудите не запускался.

Текущий Node-набор также красный: `test_page_preview.cjs` вызывает отложенную
очистку после завершения теста; заглушка MutationObserver не имеет `disconnect`,
а document/window — `removeEventListener`. Ошибка тестового окружения не
доказывает дефект настоящего браузерного API. Исправлять следует заглушки и
жизненный цикл теста, сохраняя очистку в production.

Нужно: актуализировать существующие сценарии под карточки, а не наращивать
количество старых проверок. В CI добавить общий Python/Node-набор: единственный
текущий workflow проверяет Windows-подмножество и установленный payload,
но не JS и не новую панель.

### 3. Средний приоритет: восстановление подключения объясняется неверно для Windows

`extension/background.js:103` и `extension/popup.html:53` направляют пользователя
к `python3 install_native_host.py`; настройки предлагают Homebrew и пояснения
про macOS. Это не соответствует автономному Windows-installer.

Нужно: инструкции по платформе и способу установки. Для Windows — проверка
ID расширения и repair установленного пакета. Показывать отдельно версию
расширения и помощника/пакета: manifest сейчас 3.4.0, installer 3.5.0-test.1.
Разные версии допустимы, но один номер в журнале не идентифицирует весь комплект.

### 4. Средний приоритет: накопление очереди ограничено не размером сообщения

`JobManager` ограничивает активные задачи числом 200, но завершённые записи
остаются до очистки. `native_session.py` отправляет весь снимок, а
`native_host.py:50` сериализует его без проверки размера и разбиения.

Синтетический снимок 200 реальных объектов `Job` с URL примерно по 6 КБ
получился **1 290 319 байт**, без анализа и превью. Лимит сообщения хоста в
[официальной документации Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)
— 1 МиБ. Это воспроизведение размера, не фактического отключения браузера.
Риск уже признан в README; считать транспортное разбиение из старого плана
реализованным нельзя.

Нужно до расширения массовых загрузок: явная политика размера/хранения и
контролируемая ошибка вместо обрыва канала. Не обрезать активные URL, заголовки
или задачи. Для небольших личных очередей можно оставить документированную
границу; полноценный chunking требует отдельной задачи, не автоматического
включения в полировку.

### 5. Низкий приоритет: документы описывают разные стадии

README одновременно содержит свежую информацию про direct resume и старое
«возобновление частичных файлов не реализовано». Windows JobProcess в handoff
уже production, но ряд документов ещё называет его прототипом. Старые планы
транспортной идемпотентности и разбиения нельзя читать как действующий контракт.

Нужно: одна небольшая актуальная матрица возможностей и проверенных платформ;
старые отчёты оставить как историю с явным статусом. Не переписывать весь архив.

Дополнительно Python-прогон выдал `ResourceWarning` в `windows_bundle.py:14`:
файл для SHA-256 открыт без контекстного менеджера. Небольшая локальная правка,
не причина менять архитектуру.

## Что уже сделано хорошо

- Общий Python-загрузчик обслуживает CLI, HTTP и Native Messaging. Не требуется
  переписывать приложение на другой язык или UI-фреймворк.
- Очередь, анализ, платформенные операции и модели расширения выделены в модули.
  Карточки обновляются без полной замены DOM; используются native controls,
  progress и отдельные объявления состояния.
- Есть защита от устаревшего контекста/чужого плеера, отдельные состояния отмены,
  ограниченные fallback/retry, проверка идентичности объекта при direct resume.
- Постоянная история отделена от текущих URL/заголовков; журнал использует
  ограниченный набор обезличенных полей. Это полезные границы, не основание
  заявлять полный аудит приватности.
- Windows-упаковка и владение дочерними процессами уже имеют конкретные
  артефакты и испытания. Не нужно начинать этот этап заново.

   Не подменять незаметно ранее собранный проверяемый EXE новой сборкой.
4. Проверить по нескольку типичных видео нужных владельцу сайтов, отдельно
   долгую загрузку и обрыв сети. Отказ сайта/вход отличать от дефекта приложения.
5. Проверить клавиатуру, 320/400 px, длинные названия и обе темы. Это проверка
   текущего дизайна, а не предложение нового редизайна.
6. Свести актуальные ограничения и после этого заморозить функции.

Условие остановки: пункты выше подтверждены; нет выбора чужого ролика,
необъяснимого исчезновения результата, потери истории или неработающей отмены
в принятых сценариях. Во время 1–2 недель использования вести короткий список
«что хотел сделать / что произошло», без добавления новых функций по ходу.
Число успешных локальных тестов не заменяет эту приёмку.

## Что сейчас не нужно

- Mobile, облако/аккаунты, синхронизация, AI, собственный медиаплеер/редактор.
- Новые интерфейсы: side panel остаётся основным; CLI и web сохранить, но
  не развивать параллельно без реального пользователя этих режимов.
- Полный редизайн, TypeScript-миграция всего проекта, DI-фреймворк или новый backend.
  Плотные `popup.js`/`download.py` стоит упрощать только при конкретных правках.
- Плейлисты, массовое скачивание, Windows/HLS/DASH persistence, универсальная
  поддержка сайтов — отдельные крупные обязательства, не «маленькая полировка».
- Новая оптимизация скорости без воспроизводимого узкого места на реальном
  материале. Существующие измерения сами не обещают универсального ускорения.
- Автообновление и публичное распространение как условие личного использования.
  Если появится цель публичного выпуска, отдельно вернуться к signing,
  компонентам/лицензиям, установке, обновлению и сопровождению yt-dlp.
