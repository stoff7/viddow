# Первый этап: удобный запуск и управляемая очередь

Историческая спецификация первого веб-этапа, 11 ноября 2026.
Ветка: `feat/download-workspace`. Основной интерфейс теперь — боковая панель;
текущие результаты и ограничения: [verification.md](verification.md).

## Сценарий и границы

Главный сценарий: вставить HTTP(S)-ссылку на страницу, файл или поток, отправить
её в очередь и видеть результат. Разбор HTML остаётся дополнительным инструментом.
Веб-интерфейс получает отмену, повтор ошибки/отмены, фильтры и очистку завершённых
задач. Существующие CLI и расширение продолжают использовать общее ядро загрузки.

На этом этапе нет выбора качества, предварительного получения обложек,
сохранения истории на диск и возобновления недокачанного. Повтор начинает новую
попытку с исходными параметрами. Очередь веб-сервера и задания Native Messaging
остаются разными: общий лимит между ними не обещается.

## Решения и инварианты

- Python и стандартная библиотека; yt-dlp/ffmpeg остаются внешними инструментами.
  Новые runtime-зависимости и frontend-фреймворк не нужны.
- `download.py` отвечает за загрузку и кооперативную отмену, `jobs.py` — за
  очередь и переходы состояний, `server.py` — за HTTP и проверку входных данных.
  Статические HTML/CSS/JS разделены по ответственности.
- По умолчанию выполняются две задачи; лимит настраивается через CLI сервера.
  Задачи в ожидании идут в порядке поступления. Состояние защищено блокировкой;
  HTTP возвращает снимок, а не изменяемые объекты очереди.
- Состояния: `queued → running → done | error`; отмена ожидания — `cancelled`,
  отмена выполняющейся задачи — `cancelling → cancelled`. `cancelling` занимает
  слот до фактического выхода загрузчика. Если файл уже завершён, сохраняется
  `done`, чтобы результат не потерялся из интерфейса.
- Отмена останавливает внешнюю группу процессов на POSIX и удаляет временные
  файлы. Заблокированный HTTP-запрос может ждать до сетевого таймаута (30 с).
  Готовые файлы не удаляются. Остановка сервера отменяет ожидающие и активные задачи.
- Передача страницы явно (`source_kind=page`) обходит HTTP-проверку urllib.
  В автоматическом режиме ошибки доступа к предполагаемой странице дают шанс
  yt-dlp; обычные ошибки прямого файла не маскируются.
- Заголовки браузера передаются только как параметры исходной загрузки, никогда
  не возвращаются в `/jobs`. Отображение сторонних строк — через `textContent`.
- Сервер по-прежнему доступен только на loopback, проверяет Host/Origin и JSON.
  Статические файлы отдаются по явному списку путей.

## HTTP-контракт

- `GET /health`: доступность yt-dlp/ffmpeg, каталог сохранения, лимит параллелизма.
- `POST /download`: прежние `urls`, `name`, `referer`, `headers`, `page`, плюс
  `source_kind` (`auto`, `page`, `direct`, по умолчанию `auto`). Ответ: `ids`.
- `GET /jobs`: `id`, `url`, `name`, `status`, `fraction`, `label`, `path`, `error`.
- `POST /jobs/{id}/cancel {}`: идемпотентная отмена; ответ — снимок задачи.
- `POST /jobs/{id}/retry {}`: только `error`/`cancelled`; новая задача с новым ID.
- `POST /jobs/clear {}`: удалить только завершённые записи, сохраняя файлы.
- Неизвестная задача — 404; недопустимый повтор — 409; неверный JSON — 400;
  слишком большой JSON — 413. Очередь ограничена 200 незавершёнными задачами;
  переполнение — 409. Ограничение одного пакета — 50 ссылок.

## Критерии приёмки

1. Прямой файл скачивается через главный экран без разбора HTML.
2. Третья задача при лимите 2 ожидает; отменённая ожидающая задача не запускается.
3. Отмена активной загрузки освобождает слот после остановки, удаляет `.part`,
   не меняет состояние соседних задач и не оставляет yt-dlp/ffmpeg работать.
4. Ошибочную/отменённую задачу можно повторить; готовую — нельзя.
5. HTTP 403 при автоматическом определении страницы не исключает попытку yt-dlp;
   явный режим страницы вообще не открывает URL через urllib.
6. Разбор HTML, CLI и сообщения расширения сохраняют совместимость.
7. Интерфейс работает с клавиатуры, на узком экране, в светлой/тёмной теме;
   потеря сервера отображается и опрос автоматически восстанавливается.
8. Автотесты проверяют очередь, отмену subprocess, маршрутизацию и HTTP-контракт
   на локальных фикстурах. Проверка реальных сайтов проводится отдельно.

## Идеи следующих этапов

- Карточка видео перед скачиванием: обложка, длительность, качество и дорожки.
- Сохранение истории и настроек, затем возобновление там, где источник допускает.
- Отдельное понятное состояние истёкшей ссылки с предложением получить новую
  через исходную страницу или расширение.

## Результаты проверки первого веб-этапа (исторические)

Эти 20 тестов описывают прежний прогон, а не актуальный размер Python-набора.
Регрессия веб-интерфейса после contracts/session v2 повторно проверена отдельно;
актуальный отчёт находится в [verification.md](verification.md).

- `python3 -m unittest discover -s tests -v`: 20 тестов прошли. Включают реальную
  HTTP-загрузку локального файла, отмену передачи, остановку тихого subprocess
  и его дочернего процесса, очистку временных файлов, гонку отмены с завершением,
  FIFO/лимит очереди, повтор, входные данные API и HTTP 403 → yt-dlp.
- `tests/browser_smoke.cjs`: прошёл в Chromium. Через UI проверены отправка
  формы клавишей Enter, сохранение содержимого файла, лимит двух задач,
  отмена ожидания и выполнения, повтор после ошибки/отмены, фильтрация,
  HTML-поиск и скачивание найденного, очистка истории без удаления файла,
  потеря/восстановление API, справка и Escape, сохранение темы, ширины 390/320 px
  и режим reduced motion. Необработанных JS-ошибок нет.
- Светлая/тёмная тема и мобильный экран просмотрены по скриншотам.
  [Предпросмотр главного экрана](ui-preview.png).
- Проверены синтаксис JS (включая расширение) и отсутствие whitespace-ошибок
  через `git diff --check`.
- Внешние видеосайты и установленное пользовательское расширение вручную
  не проверялись. Новые маршруты yt-dlp покрыты подменой внешнего инструмента;
  это не подтверждает поддержку конкретного сайта. Очередь расширения
  не объединена с веб-очередью.
