# Viddow: вход в разработку Windows-порта

Обновлено 12 ноября 2026. Пользователь хочет сделать приложение универсальнее,
включая Windows. Подробный [план Windows](windows-plan.md) содержит пояснения,
границы, этапы и приёмку. Статический [аудит Windows](windows-audit.md) завершён:
найденные места, приоритеты и контракт адаптера сохранены в `7c8fe20`.
Реализация начата: техническая Windows-регистрация/launcher, binary framing и
изолированный Job Object-прототип подготовлены в рабочем дереве. Текущий статус,
ограничения и команды: [docs/windows-development.md](../docs/windows-development.md).
Windows-исполнение ещё не проверено; `run_tool` пока не интегрирован с Job Object.
У пользователя есть Windows 11 x64; первая проверка на ней. Далее — доказательство
двух прототипов, затем интеграция, приёмка и упаковка.

**Продолжение:** не ожидая Windows, выполнены общий resolver всех пяти инструментов
и финализация прямого файла/ffmpeg без перезаписи при поздней коллизии; stdin
инструментов DEVNULL, stdout UTF-8. [Контракт и результаты](../docs/platform-tools-and-publication.md).
Завершающий адресный прогон на macOS: 71 тест прошёл, включая настоящие локальные
HLS video+audio, ffprobe/GIF, native-сеанс и POSIX-отмену дерева. Windows/браузерная
приёмка по-прежнему не выполнена; приложение не переустанавливалось.

## Изменения первого этапа порта

- `windows_native_install.py`: HKCU Chrome/Edge, фактические ID, повторный install,
  uninstall только своей регистрации, отказ перезаписывать чужую. Launcher `.cmd`
  с абсолютным CPython 3.11+; окна/Unicode/кодовая страница без консоли ещё требуют
  реальной проверки. Установка на этой машине не выполнялась.
- `native_protocol.py`: binary stdio Windows, полное чтение frames и проверка EOF.
  macOS по умолчанию сохраняет ID из пути и прежний `native_host.sh`.
- `prototypes/windows_job.py`: public WinAPI JOB_LIST + kill-on-close;
  [ADR](../docs/adr/windows-process-ownership.md), реальные Windows-тесты без mocks.
  Не подключать к download до проверки pipes, browser job и отказов запуска.
- Завершающие проверки на macOS: 6 новых protocol/registration тестов прошли;
  5 существующих `test_native_session.py` прошли с локальным HTTP-fixture после
  разрешённого запуска вне sandbox (в sandbox bind запрещён); WinAPI 5 skipped.
  `git diff --check` прошёл. Полный набор/браузеры/Windows не запускались.
- Ничего не установлено, не опубликовано, не закоммичено. Пользовательские
  untracked-материалы не изменены. Текущие загрузки не затрагивались.

## Состояние приложения

- Общая боковая панель Chromium, компактные карточки видео с качеством/аудио,
  прогрессом и результатом; native-host, очередь всех вкладок/окон, история.
- Выбранный плеер, автоматическая подготовка HLS/DASH, GIF, раннее намерение
  скачать, восстановление после ошибок страницы, группировка ошибок попытки.
- Подтверждение отдельных HLS-дорожек через ffprobe и объединение X video/audio.
- Web/CLI сохранены; веб-очередь отдельная. Не вводить daemon ради Windows.
- README описывает архив с Python-кодом; yt-dlp и ffmpeg ставятся отдельно.
  Удобный Windows-установщик с инструментами пока только предложение.

## Аудит Windows

- P1: Known Folder Downloads, два reveal, Windows device names, гонка финализации,

- Дополнительно: зависимости внутри yt-dlp, stdin инструментов, отсутствие
  межпроцессного lock журнала на Windows, путь logs рядом с программой.
- macos_metadata.py уже защищён проверкой ОС. Очередь/EOF общие; менять их
  архитектуру ради Windows не требуется. Framework/daemon не вводить.
- В [аудите](windows-audit.md) сохранён контракт platform_support.py и ссылки
  на официальные Chrome/Edge/WinAPI. Launcher, Job Object и упаковка ещё не реализованы.

## Следующие действия

1. Прочитать docs/windows-development.md и исполнить подготовленные прототипы на
   Windows 11 x64 пользователя с CPython 3.11+. Не считать mocks на macOS приёмкой.
2. Подтвердить реальную связь Chrome/Edge→host, launcher/Unicode/stdio и HKCU
   install/uninstall в отдельной VM/учётной записи. Без публичного установщика.
3. Отдельно доказать владение деревом процессов: назначение до запуска кода,
   потомок после выхода родителя, отмена/EOF/авария, отсутствие утечек handles.
4. platform_support.py/resolver, кодировки/DEVNULL и два прежних os.replace уже
   исправлены общей частью; продолжить Known Folder, Explorer, temp/ACL/журнал.
   Процессную Windows-часть подключать после доказательства прототипов.
5. Проверить локальный реальный video+audio, отмену, историю и обе ОС;
   лишь после этого выбирать упаковку и готовить Windows-артефакт.
