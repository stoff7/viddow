# Отчёт: начало Windows-порта Viddow

Дата: 12 ноября 2026 года. Репозиторий: `downloader`, ветка
`feat/download-workspace`, HEAD на момент отчёта — `7f6f977`.
Отчёт охватывает начало порта и последующие общие исправления в этой сессии.
Изменения находятся в рабочем дереве; коммиты и публикация не выполнялись.

## Результат

Подготовлен первый технический Windows-путь Native Messaging и отдельный
прототип владения деревом процессов. В общий загрузчик уже интегрированы
безопасная финализация прямых файлов/результатов ffmpeg, единый поиск инструментов
и явные параметры потоков дочерних процессов.

Общие изменения прошли адресные проверки на macOS, включая настоящую локальную
загрузку HLS с раздельными видео и аудио. **Готовность Windows-порта пока не
подтверждена:** Windows-код не исполнялся, Job Object не подключён к рабочему
`run_tool`, связь Chrome/Edge → host на Windows не проверена.

У пользователя есть Windows 11 x64, но проверка на этой машине отложена.
В текущей рабочей среде доступна macOS. Для технического Windows-прототипа выбран
CPython 3.11+ `python.exe`; упаковка и комплектный runtime ещё не выбраны.

## Выполненные изменения

### 1. Native Messaging: регистрация и launcher

В [install_native_host.py](../install_native_host.py) добавлена отдельная ветка
Windows. Она выбирается до обращения к macOS-каталогам профилей. Реализация
Windows вынесена в [windows_native_install.py](../windows_native_install.py).

Подготовлено следующее поведение:

- Реальный ID распакованного расширения принимается через `--extension-id`.
  Разрешены ровно 32 буквы `a–p`; можно передать несколько ID для Chrome и Edge.
  Windows-регистрация не использует macOS-вычисление ID из пути.
- Manifest содержит абсолютный путь к launcher и явный список `allowed_origins`.
- Регистрация выполняется в HKCU Chrome/Edge через winreg с явным выбором
  32-bit registry view. Обязательные права администратора и изменение PATH
  не предусмотрены.
- Повторный install обновляет свою регистрацию. Обнаружение чужого manifest
  вызывает отказ до записи файлов. Uninstall снимает своё default value,
  удаляет пустой ключ и сохраняет другие значения/подключи.
- Технический `.cmd` закрепляет абсолютный путь к Python, через который запущен
  установщик, передаёт аргументы браузера и не предназначен для вывода в stdout.
  Генерируемая папка `windows-native/` добавлена в `.gitignore`.
- На Windows отвергается `--user-data-dir`: отдельный профиль браузера не
  изолирует HKCU-регистрацию.

macOS по умолчанию сохраняет прежний shell launcher, каталоги регистрации и ID
из пути. Установщик не применялся к пользовательским профилям ни на одной ОС.

Ограничения: `.cmd` остаётся промежуточным launcher. Его работа без консоли,
скрытие окна, кириллица, кодовая страница и политики запуска реальных браузеров
не проверены. Пути с `%`, кавычками и переводами строк отклоняются. Запись ключей
двух браузеров не является транзакцией: ошибка доступа может оставить частичную
регистрацию, устраняемую повторным запуском после исправления причины.

### 2. Двоичный протокол host

Добавлен [native_protocol.py](../native_protocol.py), подключённый к общему
[native_host.py](../native_host.py).

Reader полностью дочитывает заголовок и payload при коротких чтениях, различает
чистый EOF и оборванное сообщение, проверяет размер и принимает UTF-8 JSON-объект.
Собственный лимит приложения остался 1 МиБ. На Windows предусмотрено включение
binary mode для stdin/stdout; отсутствие потоков у runtime вызывает явную ошибку.

Схемы session v2/history v1 и команды очереди не менялись. Регрессии native-сеанса
на macOS прошли; Windows binary mode и настоящая связь с браузером ещё требуют
платформенного исполнения.

### 3. Изолированный Job Object-прототип

Создан [prototypes/windows_job.py](../prototypes/windows_job.py). Механизм
использует публичные WinAPI через ctypes: создание процесса с атрибутом JOB_LIST,
отдельный ненаследуемый job и kill-on-close. Новых Python-зависимостей нет.

В прототипе предусмотрены сериализованный повторный `stop()`, завершение job,
ожидание отсутствия активных процессов и закрытие handles. При таймауте владение
сохраняется для повторной остановки. Отказ назначения не подменяется обычным
невладеемым запуском процесса.

Выбор, альтернативы и критерии принятия записаны в
[ADR](adr/windows-process-ownership.md). Для реального WinAPI подготовлены
[тесты](../tests/test_windows_job.py) и
[безвредная процессная fixture](../tests/fixtures/windows_process_tree.py):
ранний выход родителя, одновременные stop, EOF и аварийный выход контроллера,
nested job, отмена до/во время spawn и повторные циклы создания handles.

Это кандидат для дальнейшей интеграции. Он пока не реализует production pipes,
полный Popen-интерфейс и окружение. Ограничения настоящего browser job не
воспроизведены. На macOS все пять Windows-тестов пропущены по ОС. Рабочий
Windows-путь отмены по-прежнему останавливает только родителя.

### 4. Финализация без перезаписи существующего файла

Исправлены два прежних вызова `os.replace` в [download.py](../download.py):
прямое сохранение и завершение загрузки через ffmpeg.

Раньше пустая `.part`-резервация защищала от совпадения имён между загрузками,
но не от файла, созданного другим приложением перед финальным `os.replace`.
Теперь `finalize_file` вызывает `move_file_no_replace`; при конфликте получает
другую резервацию и повторяет попытку.

Пример: во время загрузки появился чужой `video.mp4`. Его содержимое сохраняется,
а результат загрузки записывается как `video (1).mp4`. В историю и metadata
передаётся фактический итоговый путь. Повторная коллизия снова меняет имя.

macOS использует `renamex_np` с `RENAME_EXCL`, Windows — `os.rename`, прочие POSIX —
link/unlink. Ошибка неподдерживаемой операции не приводит к fallback с заменой.
Отмена проверяется перед попыткой; после успешной фиксации готовый файл сохраняется.
При ошибках убираются собственные временные части и дополнительные резервации.

Проверены поздние и повторные конфликты, dangling symlink, ошибки/отмена и
конкурирующие независимые процессы. Это исправление двух операций приложения;
собственная финализация yt-dlp с `--no-overwrites` не переписывалась. Внешние и
сетевые файловые системы не проверялись.

### 5. Общий resolver и окружение инструментов

Добавлен [platform_support.py](../platform_support.py). Общий resolver обслуживает
yt-dlp, ffmpeg, ffprobe, Deno и Node. Прежние вызовы `shutil.which` заменены в
download, inspector, preview, probe, source_auth, native session и web health.

Приоритет: явный абсолютный исполняемый путь → `bin/` рядом с проектом → допустимые
абсолютные каталоги PATH. Для macOS сохранён доступ к стандартным Homebrew bin.
Пустой/неверный явно настроенный путь вызывает ошибку без запасного поиска.
Текущий каталог, пустые и относительные элементы PATH исключены; `.cmd`/`.bat`
не принимаются как инструменты, на Windows автоматически ищутся `.exe`.

Настройки доступны через `VIDDOW_YT_DLP`, `VIDDOW_FFMPEG`, `VIDDOW_FFPROBE`,
`VIDDOW_DENO`, `VIDDOW_NODE`. Диагностика сохраняет прежние bool-поля `tools`;
неверная настройка даёт false, попытка действия сообщает ошибку настройки.
Обнаружение executable не считается проверкой его версии и возможностей.

yt-dlp получает абсолютный `--ffmpeg-location`. Если найдены ffmpeg и ffprobe,
проверяется их согласованное соседнее расположение. Для YouTube выбранный Deno
либо запасной Node передаётся абсолютным путём. Политика доступа к cookies
не менялась; личные cookies не читались для проверки.

`run_tool` получает stdin DEVNULL и явный UTF-8 stdout. Для диагностического stderr
используется UTF-8 с заменой ошибочных байтов. Окружение копируется для дочернего
процесса, его PATH исключает неявный cwd; глобальный PATH не меняется.
POSIX session/killpg и callbacks сохранены.

Подробный контракт и ограничения:
[platform-tools-and-publication.md](platform-tools-and-publication.md).

## Проверки и доказательства

| Прогон | Результат | Что подтверждает |
| --- | --- | --- |
| Первый этап: `test_windows_port.py` | 6 прошли на macOS | Framing, ID, генерация launcher, контракт registry с подменённым API, сохранение macOS-профиля регистрации |
| Первый этап: `test_native_session.py` | 5 прошли на macOS | Настоящий Python-host, очередь, отмена/EOF, команды и legacy-совместимость |
| Windows Job Object: `test_windows_job.py` | 5 пропущены по ОС | Платформенного доказательства нет |
| Общие исправления: адресный набор из 8 модулей | 71 прошёл на macOS, без пропусков | Финализация, resolver, ядро загрузок, анализ, дорожки, HTTP, native-сеанс и настоящие media tools |
| `git diff --check` | Успешно | Оформление diff |

Пять тестов native-сеанса входят и в завершающий набор из 71; эти числа не нужно
суммировать как независимое покрытие. Пропуски Windows-тестов не являются успешной
проверкой Windows.

Команда завершающего прогона:

```sh
PYTHONPATH=.:tests python3 -m unittest test_platform_support test_download test_inspector test_media_tracks test_source_auth test_server test_native_session test_tracks_offline
```

В локальном media-сценарии настоящие ffmpeg/yt-dlp обрабатывали HLS с отдельными
video/audio; ffprobe подтвердил обе дорожки в результате. Также проверено
ограниченное GIF-превью. Эти проверки использовали локальные fixtures, а не
внешние сайты или пользовательские профили.

Sandbox запрещал bind даже на 127.0.0.1; адресные HTTP/native-прогоны выполнены
после разрешённого запуска вне sandbox. Первый прогон общих исправлений обнаружил
ошибку нового теста: ожидалось отсутствие yt-dlp, хотя допустимый Homebrew fallback
должен был его находить. Ожидание исправлено на проверку исключения cwd/относительных
путей; завершающий прогон прошёл полностью.

При подготовке этого отчёта исходники, Git и записи результатов сверены заново;
тесты повторно не запускались. Полный набор и browser smoke не выполнялись.

## Сохранённые границы

Рабочее приложение не переустанавливалось, пользовательские браузеры не
перерегистрировались, текущие загрузки не затрагивались. Архитектура очереди,
постоянная история, UI, отдельный веб-режим и macOS launcher сохранены; daemon
и новые внешние зависимости не добавлены.

Релиз v3.4.0, его тег и интеграционная main не изменялись. Коммиты, merge, push,
новый пакет и публикация не выполнялись. Пользовательские `.agents/`,
`handoff/experiments/` и `skills-lock.json` сохранены. Ветка содержит также новые
untracked-файлы реализации и документации; один `git diff --stat` не отражает
весь объём работы.
