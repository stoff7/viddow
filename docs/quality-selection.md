# Этап 4: качество и звуковые дорожки

## Контракт и инварианты

- Основной UI — sidePanel. Главный экран и автоподготовка описаны в [main-screen-ux.md](main-screen-ux.md); дополнительные действия скачивания работают без анализа.
- Подготовка запускает сетевые запросы и yt-dlp в режиме simulate. Текущая страница подготавливается автоматически после обнаружения видео; произвольные пойманные адреса автоматически не анализируются. URL/query/заголовки не обрезаются.
- Один отдельный анализ на Native Messaging-сессию. Он не занимает слот загрузки
  и не блокирует cancel/download/EOF. Отмена и общий таймаут останавливают процесс.
- Анализ хранит один источник с заголовками в памяти хоста. Публичный снимок
  содержит метаданные/ID форматов, но не media URLs/заголовки из JSON yt-dlp.
- HLS master/media определяется по тегам содержимого манифеста, а не имени или
  числу форматов. Для прямого HLS анализ может сделать дополнительный GET
  манифеста; одноразовая ссылка может истечь. Ошибка не отключает обычную загрузку.
- Выбор — точные ID форматов, без произвольного выражения yt-dlp. Несколько
  звуковых дорожек доступны для видео без встроенного звука и требуют ffmpeg.
  Неизвестный состав обозначается явно. Автоматического fallback качества нет.
- `download` с `analysis_id` проверяет актуальность анализа и принадлежность ID
  результату. Исходные параметры и выбор копируются в новую задачу; существующие
  задачи не меняются. Retry использует тот же выбор.
- Название, обложка, длительность/live и подписи качества выводятся из metadata.
  Неизвестные значения не подменяются догадками. Обложка необязательна.
- Без новых runtime-зависимостей, сервера/daemon и frontend-фреймворка.

## Протокол session v2 (дополнение)

`inspect` принимает те же поля источника, что download (один URL), и возвращает
`{analysis_id}`. `state.analysis` содержит `id`, исходный `url`, `status`
(`running/cancelling/done/error/cancelled`), `result` или `error`.
`inspect_cancel` принимает ID анализа. Ответы команд быстрые; результат анализа
публикуется через state. Таймаут анализа — 30 с, отдельный от таймаута reply.

`download` с `analysis_id` и `format_ids` берёт исходный контекст из памяти
анализа. После нового анализа/сессии прежний ID отвергается. В snapshot задачи
выбор виден как `format_ids` и `format_label`. Он не записывается в настройки.

## Приёмка

1. HLS master с несколькими разрешениями и двумя языками: выбранные разрешение
   и звуковые потоки подтверждены ffprobe выходного файла.
2. Media-плейлист и master с одним вариантом различаются по содержимому.
3. Неизвестная длительность/live, отсутствие обложки/языка/кодеков отображаются
   честно. Форматы не называются лучшими по имени/порядку.
4. Истёкшая ссылка, отсутствие yt-dlp/ffmpeg, таймаут и отмена анализа не ломают
   Native Messaging и обычную загрузку. EOF останавливает анализ и задачи.
5. Смена вкладки/закрытие панели не изменяет источник/выбор существующей задачи.
   Retry сохраняет ID форматов. Чужой analysis/session ID отвергается.
6. Клавиатура, обе темы и 320 px работают. Автоподготовка не создаёт загрузку и не заменяет открытый выбор другого источника.

Основа: [документация yt-dlp](https://github.com/yt-dlp/yt-dlp#format-selection).

## Детали и границы

Анализ использует `--ignore-config --simulate --dump-single-json`, поэтому
пользовательский yt-dlp config не запускает побочные действия анализа.
Выбранная загрузка тоже игнорирует config, чтобы соответствовать анализу;
обычное скачивание сохраняет прежнее поведение.
ID ограничены буквами/цифрами/`_-.` (до 128 символов, не с дефиса), передаются как
строковые literal-фильтры `all[format_id='…']`, а не выражения пользователя.
Кавычки существенны для числовых ID. Поддерживается до 9 форматов за раз;
недоступный выбранный формат даёт ошибку без fallback на другое качество.

С ffmpeg включается запись метаданных для языковых меток; сырой infojson и
главы не вкладываются. Без ffmpeg можно выбрать один готовый формат/видео без
звука; объединение недоступно. Для формата с уже встроенным звуком дополнительные
отдельные дорожки пока не предлагаются.
Сырой JSON ограничен 8 МиБ, нормализованный результат — 300 форматами и 256 КиБ.
Если источник больше/не поддерживается, обычное скачивание остаётся доступным.
HLS GET классификации ограничен 1 МиБ и коротким сетевым таймаутом; при отказе
CDN тип остаётся неизвестным. Анализ не гарантирует, что временный URL будет
действовать при последующем скачивании.

Live/отсутствующие поля/ffmpeg проверены локальными unit-фикстурами, не внешним
live-сайтом. Обложка появляется только когда её возвращает источник; у локального
HLS её нет. Внешние авторизованные источники и другие браузеры не проверялись.
Этот отчёт относится к этапу 4. Постоянная история добавлена позже в
[этапе 5](persistent-history.md); этап 6 ещё не реализован.
Обычные автотесты не открывают Finder; настоящий `open -R` — только с явным
`VIDDOW_TEST_FINDER=1`. Протокол reveal проверяется с подменой системного вызова.
