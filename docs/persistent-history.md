# Этап 5: история между запусками браузера

## Решения и границы

- История принадлежит профилю расширения и хранится в `chrome.storage.local`.
  Python не получает нового дискового хранилища/daemon. Веб-очередь самостоятельна.
- Настройки папки, параллелизма и темы уже сохраняются; их формат не меняется.
- Схема истории: `{version: 1, jobs: [...]}`. Запись содержит ID, название,
  исходную страницу без credentials/секретных query/fragment, origin источника,
  дату, итог, путь файла и безопасную подпись выбранного формата.
- Полный URL загрузки, Cookies/Authorization/Referer, сырой error/прогресс,
  метаданные анализа и старые format IDs в историю не попадают. Очистка
  постоянной проекции не меняет полные ссылки/заголовки текущей загрузки.
- Query исходной страницы удаляется. Исключение — identity-параметр `v` у
  YouTube watch; прочие query не сохраняются. Если удаление параметров могло
  изменить страницу, автоматический повтор по такой записи недоступен.
- На старте восстанавливаются только записи, без запуска исполнителя.
  queued/running/cancelling становятся `interrupted`. Автоматического повтора нет.
- ID восстановленных задач учитываются при выдаче новых ID; новый session ID
  по-прежнему защищает команды от старой сессии.
- «Повторить со страницы» запускает свежий анализ исходной страницы без старых
  заголовков/форматов. Пользователь подтверждает новый выбор в панели.
  Если исходная страница не сохранена, панель предлагает вставить новую ссылку.
- Файл после восстановления проверяется на существование. Отсутствующий файл
  не превращает прошлое успешное скачивание в ошибку; Finder для него недоступен.
- Очистка завершённых удаляет также восстановленные записи из хранилища,
  сохраняя файлы и активные задачи. Finder в автотестах не открывается.

## Версия и восстановление данных

Первая публичная схема — version 1. Поддерживается нормализация unversioned
массива (version 0) в новую схему. Повреждённые записи пропускаются с сообщением;
невалидный контейнер не мешает скачиванию. Неизвестная будущая версия сохраняется
нетронутой, запись истории временно отключается с видимой диагностикой.
Ошибки записи не маскируются статусом «история сохранена».

Native Messaging принимает при начале сессии нормализованную историю и
восстанавливает записи в JobManager. Источник истины активных задач — хост;
источник восстановления между запусками — безопасная локальная проекция.
Промежуточный прогресс не пишется на диск. Изменения состава/итога очереди
сохраняются последовательно, повторная запись одинаковой проекции пропускается.

## Приёмка

1. Реальный перезапуск отдельного браузерного профиля сохраняет done/error,
   путь, выбранную папку/лимит/тему. Сеть без действия пользователя не запускается.
2. Незавершённая задача после перезапуска — interrupted, без продолжения.
3. Повтор страницы получает свежие форматы/адреса; старые headers и IDs отсутствуют.
4. Повреждённая запись и миграция version 0 не ломают остальные записи;
   неизвестная будущая версия не перезаписывается.
5. Удалённый файл отмечен в UI; очистка истории не удаляет существующие файлы.
6. В фактическом постоянном JSON нет сырых URL загрузки, подписанных query,
   Cookies/Authorization, сообщений ошибок с секретами и metadata анализа.

Текущие ограничения предыдущих этапов остаются в этапе 6 по просьбе пользователя.

Хранится только один явно описанный whitelist полей; сырые ошибки заменяются
HTTP-кодом или общим текстом. Полные параметры текущего скачивания сохраняются
в памяти. Получение свежей ссылки через страницу не гарантирует авторизацию:
если сайт требует новый вход/контекст, пользователь заново открывает источник.
Исходный page URL сохраняется без credentials/query/fragment, с описанным
исключением для YouTube `v`; если очищение меняет идентичность страницы,
`page_retry` выключен. Это политика постоянной истории, не изменение URL загрузки.

дополнительный звук у combined-форматов и внешние браузеры/источники остались
для этапа 6, как договорились с пользователем.
