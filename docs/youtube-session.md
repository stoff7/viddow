# YouTube: сеанс браузера и подготовка

Часть этапа 6, 11 ноября 2026. Пользователь сообщил два разных отказа:
`Sign in to confirm you’re not a bot` при извлечении страницы и `curl (28)` при
загрузке потока с manifest.googlevideo.com. Сеанс пользователя — Vivaldi, вход
выполнен. Телефонная версия отложена.

## Изменения

- В панели «Настройки → Сеанс YouTube» можно явно выбрать Vivaldi (или другой
  поддерживаемый yt-dlp браузер). По умолчанию вход браузера не используется.
- Выбор применяется к анализу страницы, новой/выбранной загрузке и следующему
  retry. Параметры уже существующей задачи не меняются. Изменение настроек
  доступно после отмены/завершения активной очереди.
- При смене сеанса готовый анализ сбрасывается во всех панелях. Старый
  `analysis_id` отвергается: нужно заново запросить качество и выбрать формат.
  Выполняющийся анализ отменяется; новый доступен после завершения отмены.
  Поздний результат или ошибка не возвращают старые форматы. Изменение только
  папки/параллелизма и отклонённое сохранение настроек анализ не сбрасывают.
- yt-dlp читает последний активный профиль выбранного браузера штатным
  `--cookies-from-browser`. Это происходит только для URL доменов YouTube,
  не для X/VK/других сайтов и не для отдельного googlevideo CDN URL.
- Cookie jar остаётся в процессе yt-dlp. `--no-cookies` отменяет экспорт в файл,
  `--no-cache-dir` отключает файловый cache при использовании сеанса.
  В настройки записывается только имя браузера; значения cookies/сырой jar
  не возвращаются в state и не попадают в историю. Автотесты читают только фикстуры.
- Для YouTube не навязывается стандартный User-Agent Viddow при анализе и
  выбранной загрузке. Доступный Node включается, если нет Deno; установленные
  EJS-компоненты остаются обязанностью yt-dlp. Удалённые компоненты не включаются.
- Ошибка входа предлагает открыть настройку сеанса. Ошибка/отмена задачи с
  известной исходной страницей предлагает **«Обновить ссылку»**:
  это новый явный анализ, а не бесконечный повтор устаревшего CDN URL.
  Для найденных потоков на вкладке YouTube эта кнопка доступна сразу.
  Анализ страницы не получает старые CDN-заголовки; выбранный сеанс применяется
  штатно. Пользователь заново выбирает формат и подтверждает загрузку.
- `curl (28)` выделен как сетевой таймаут, без утверждения об истечении ссылки.
  Обновление ссылки не гарантирует устранение проблем сети. Пойманные браузером
  адреса продолжают обновляться по реальным запросам плеера; постоянных фоновых
  проверок подписанных URL нет: универсального надёжного способа определить
  срок действия ссылки до скачивания не существует.
- До первых байтов отображается «Подготовка · N с». Отмена доступна. Число
  повторов ограничено (`retries=1`, `fragment-retries=2`, `extractor-retries=1`);
  отсутствующие фрагменты больше не пропускаются ради ложного done.
- Понятные причины отделяют вход, отказ 403, истёкшую ссылку, сеть/таймаут,
  отсутствующую зависимость и папку. Исходный текст доступен в «Технической
  причине» только в текущей сессии; постоянная история его не сохраняет.

## Проверка

Точечная проверка исправления смены сеанса, 11 ноября 2026:

- Два новых регрессионных теста сначала воспроизвели дефект, затем прошли:
  Vivaldi → «Не использовать» / Chrome, отказ старого ID из другой панели,
  новый анализ с текущим выбором, отмена текущего анализа и поздний ответ/ошибка.
- Прошли 21 тест `test_source_auth` и `test_inspector`, два TLS fallback-теста,
  проверки синтаксиса трёх изменённых JS-файлов и `git diff --check`.
- Личные cookies не читались. Несколько настоящих панелей, живой YouTube и
  полный набор в этой проверке не запускались.

Результаты предыдущей реализации этапа 6 (не новый полный прогон):

- 52 Python-теста прошли, включая scope браузерного сеанса, opt-in, отсутствие
  экспорта cookies, передачу выбора в анализ/скачивание/retry и heartbeat до байтов.
- Браузерный mock прошёл выбор Vivaldi и переход от ошибки к исходной странице;
  живые cookies пользователя при этом не читались.
- Настоящий native-smoke на локальных MP4/HLS и двух языках прошёл; веб-regression
  прошла. Для анализа media-плейлиста тест теперь читает один согласованный
  снимок вместо сравнения двух состояний в разных моментах времени.
- Анонимный metadata-запрос конкретного ролика пользователя повторил отказ
  «подтвердите, что вы не бот». Это подтверждает отказ без сеанса, но не доказывает
  успешную загрузку с авторизацией.
- Публичные корни YouTube и manifest.googlevideo.com отвечают. На корне CDN
  получен ожидаемый 404 как через urllib, так и curl_cffi с Chrome impersonation
  и без него. Доступность корня **не подтверждает** доступность подписанного
  манифеста или сервера сегментов. Сетевой таймаут отдельного потока пока нельзя
  считать исправленным только настройкой cookies.

## Пользовательская проверка

1. Отменить зависшую загрузку, затем обновить распакованное расширение Viddow
   на `vivaldi://extensions` (кнопка ⟳). Это также перезапустит Python-помощник.
2. В панели открыть настройки, выбрать **«Сеанс YouTube → Vivaldi»** и сохранить.
   macOS может запросить доступ для чтения сеанса браузера.
3. Открыть ролик в том же профиле Vivaldi и убедиться, что он воспроизводится.
4. Нажать **«Качество и звук на странице»**, затем подтвердить нужный формат.
   При ошибке старого потока — «Обновить ссылку».

Кнопка обновления и отдельный текст curl (28) добавлены после указанных выше
прогонов. Полный набор не перезапускался по просьбе пользователя; эти изменения
предстоит проверить вручную в Vivaldi.

Настоящий сеанс пользователя остаётся отдельной проверкой по его явному выбору
в настройке. Сеанс может помочь авторизации, но не гарантирует снятие отказа
YouTube, сетевого ограничения или доступность истёкшего CDN URL.
