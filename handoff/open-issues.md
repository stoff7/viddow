# Проверенные открытые вопросы

## 1. Браузерный тест расширения не проходит смену вкладки — P0

Файл: `tests/extension_smoke.cjs`, строка 141 на момент передачи.

Симптом:

```text
page.waitForFunction: Timeout 30000ms exceeded.
Ожидание: #tabTitle === 'Другая вкладка'
```

Последовательность: открыть другую страницу → `other.bringToFront()` → нажать
`[data-view=streams]` в UI расширения → ждать заголовок другой вкладки.

**Факт:** расширение реально загружено в отдельный профиль Chromium. Но UI
открыт обычной вкладкой `chrome-extension://…/popup.html`, а не как настоящий
контейнер sidePanel. Native Messaging подменён только внутри тестового worker.

**Гипотеза, пока не подтверждена:** клик по UI-вкладке снова активирует саму
вкладку расширения, и `tabs.query({active:true, windowId})` возвращает её.
Это может быть проблемой тестового окружения, а не настоящей боковой панели.

Следующее действие: вывести tab.id/url/windowId и результат `tabs.query` до/после
клика, сопоставить с `ownWindow` в `popup.js`. Если причина в тесте — проверять
правильный контейнер либо отделить имитацию UI от реального переключения вкладок.
Не добавлять в продукт пропуск любых extension-страниц только ради зелёного теста.

Не выполнены последние шаги теста: ручная ссылка на другой вкладке, разрыв
native-порта, итоговое утверждение об отсутствии необработанных JS-ошибок.

## 2. Нестабильный тест HTTP 413 — P0

Файл: `tests/test_server.py`, `test_input_and_origin_validation`, строка 128.
Последний полный прогон: 23 теста, 1 ошибка, остальные 22 прошли.

```text
connection.request(... body = ' ' * (MAX_BODY + 1))
ConnectionResetError: [Errno 54] Connection reset by peer
```

Сервер проверяет Content-Length и возвращает 413, не читая избыточное тело.
**Вероятная причина:** HTTP/1.0 закрывает соединение, пока клиент ещё отправляет
тело. В прежних прогонах этот тест проходил; последняя ошибка не исправлена.

Сначала отдельно проверить отказ по завышенному Content-Length без отправки
тела: `putrequest`/`putheader`/`endheaders` → `getresponse`. Сервер не должен ждать
большое тело. Затем определить, нужен ли дополнительный тест фактической отправки
тела и как трактовать закрытие соединения. Не убирать лимит и не читать
неограниченное тело ради результата теста. Не скрывать любые сетевые ошибки.

## 3. Проверки реальной панели и локального помощника — P0

Python-тесты проверяют настоящий дочерний процесс `native_host.py` и локальный
HTTP-источник. Браузерный тест проверяет реальный webRequest и UI, но заменяет
connectNative. Их результаты ещё не доказывают полный рабочий путь
«настоящая sidePanel → зарегистрированный Native Messaging → файл».

Нужен один такой сквозной сценарий в явно выбранном тестовом профиле/браузере,
с безопасным локальным файлом. Не менять пользовательский профиль молча ради теста.
Также проверить, что закрытие/повторное открытие панели сохраняет задачи, а
закрытие браузера останавливает помощник и дочерние процессы.

## 4. Документация отстаёт от расширения — P1

README всё ещё описывает старую кнопку «Скачать страницу (yt-dlp)» и не содержит
новый протокол сессии/возможности панели. В заголовке `native_host.py` описаны
только прежние одиночные команды. `docs/first-improvements.md` содержит успешные
результаты предыдущего этапа, но не последние регрессии. Обновить после проверок,
не переписывая результаты в «всё прошло» заранее.

## 5. Ещё не подтверждённые граничные сценарии — P1

Это пункты проверки, а не доказанные дефекты:

- Реальный reconnect native-порта, таймаут/ошибка до ready и защита от команд
  со старым session ID после повторного подключения.
- Синхронизация двух открытых панелей в разных окнах; выбор вкладки своего окна.
- Настройки папки/параллелизма: сохранение, запрет во время работы, изменение
  после отмены, показ уже готового файла из прежней папки.
- Недоступная папка, отсутствующий yt-dlp/ffmpeg, ошибки сайта и истёкшие ссылки.
- Заголовки при повторном наблюдении URL: кнопка должна отправить свежие значения.
- Старые одиночные Native Messaging-команды download/reveal после добавления session.
- Потоки при редиректах/SPA-навигации и долгой работе вкладки; актуальность списка.
- Лимит размера Native Messaging-сообщений при большом числе задач/длинных URL:
  проверить до объявления поддержки больших очередей; не терять активные задачи.
