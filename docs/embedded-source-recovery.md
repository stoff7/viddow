# Восстановление после ошибки встроенного ролика

12 ноября 2026. Основание — реальные записи `logs/viddow.jsonl` и сообщение
пользователя: страница yummyanime.tv сообщает о требовании входа в YouTube.

## Подтверждённая цепочка

В журнале три анализа 622a625d…, 896c3c17… и 4c876bb2…: опрос DOM заканчивается
page_context_unavailable за 3001–3006 мс; анализ страницы затем за 2,5–3,5 секунды
завершается authentication_required. Нет prepare_begin, prepare_batch_start и
новой download_queued для этих попыток. В том же журнале ранее зафиксированы
три HLS-источника. По предоставленной сырой ошибке yt-dlp выбрал встроенный
YouTube Qx01pn9l-6g; это не подтверждение, что он является выбранной серией.

Две причины: context=null не создавал VideoPreparation вообще; автоматический
fallback допускал только unsupported_source, а authentication_required завершал
цепочку. Картинка и iframe не должны быть обязательны для сетевого восстановления.

## Контракт исправления

- Область подготовки привязана к tabId и поколению основного документа из
  webRequest/session-кеша. URL вкладки проверяется через tabs.get, уже разрешённый
  существующими host_permissions. При недоступном DOM возвращается явный сетевой
  контекст domAvailable=false, без выдуманных video/frame/poster/duration.
- DOM-контекст может появляться/исчезать в пределах того же поколения, не отменяя
  подготовку и ранее нажатую кнопку «Скачать». При доступном DOM по-прежнему
  проверяются media keys. Новая навигация, вкладка, native-сеанс и явная отмена
  сохраняют ограничения отложенного действия.
- Недоступный allFrames не опрашивается бесконечно: после неудачи выдерживается
  пауза перед новой DOM-проверкой. Известные скрытые документы того же поколения
  сохраняются как исключения. Сетевые данные всегда могут дать свои GIF и форматы.
- На сторонней странице ошибки извлечения встроенных роликов (в том числе YouTube
  auth/403/timeout) допускают одну ограниченную партию наблюдаемых HLS/DASH. Это
  не чтение cookies и не попытка обойти вход. Оригинальные URL YouTube сохраняют
  свои сообщения о сеансе. DRM/отсутствие инструмента не запускают автоповтор.
- При ошибке встроенного YouTube сообщение относится к встроенному ролику, а не
  утверждает, что исходный сайт или выбранная серия требуют YouTube-входа.
- Партия не повторяется после своей ошибки; полный файл скачивается только по
  явному нажатию. Заголовки/query кандидатов и существующая очередь сохраняются.

## Проверки (только завершающим этапом)

Модель политики для сторонней страницы и прямого YouTube; сетевой контекст при
неответившем iframe, смене поколения и восстановлении DOM; реальный native smoke
с ошибкой встроенного YouTube на локальной странице и действительным HLS.
Личные cookies не читать. Затем прочитать журнал всей цепочки до job_done.

### Результат завершающей проверки

- 51 JS-тест и 35 Python-тестов прошли; синтаксис background/popup,
  компиляция изменённых Python-модулей и git diff --check без ошибок.
- extension_smoke.cjs: PASS, включая две панели, отмену, очередь, историю,
  автоматический анализ и интерфейс 320/400 px.
- automatic_video_native_smoke.cjs: PASS. На локальной странице тестовый shim
  воспроизводит только ошибку встроенного YouTube; реальные yt-dlp и ffmpeg
  анализируют HLS, создают GIF и скачивают выбранный файл.
- В /tmp/viddow-auto-native/trace.jsonl подтверждена цепочка
  embedded_source_error → prepare_batch_start (2 кандидата) → analysis_done →
  prepare_download/download_queued → job_done (job_id=5). Сквозная проверка также
  подтверждает одну карточку для трёх связанных ошибок.
- Реальный yummyanime после правки не перепроверялся; поддержка именно его CDN
  и текущего сеанса не выводится из успеха локальной фикстуры.

## Использованные руководства

Прочитаны установленные .agents/skills/chrome-extensions и modern-web-guidance.
Chrome guidance применён к состоянию MV3 и ошибкам async API. Уточнение разрешений
сверено с https://developer.chrome.com/docs/extensions/reference/api/tabs#permissions:
существующее <all_urls> уже даёт доступ к url/title совпадающих HTTP(S) вкладок,
поэтому дополнительное tabs-разрешение ради этой правки не добавляется.

Modern Web Guidance: выполнены два поиска по отмене асинхронных операций и ошибкам
запросов, прочитан validate-origins. Применён совместимый с Chrome 116 разбор через
new URL() с проверкой protocol и точных границ домена; цитата fallback-рекомендации:
«fall back to parsing URLs with `new URL()`». Новый Origin API не требуется.
