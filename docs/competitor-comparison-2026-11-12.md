# Viddow и Video DownloadHelper: повторная проверка

12 ноября 2026. Проверена локальная копия DownloadHelper 10.7.1.2 из Vivaldi,
не утверждается, что именно эта версия активна в пользовательском профиле.
Код конкурента не переносился. Приложение Viddow не изменялось.

## Метод и ограничения

- Оба расширения загружены в отдельный Chromium-профиль. Внешние домены
  отключены, личные cookies/вкладки не используются.
- Общий локальный источник: HTML с video.poster, master HLS с вариантами
  1920×1080 / 1280×720; дочерние VOD-плейлисты содержат EXTINF 10 и ENDLIST.
  Сегмент возвращает 404: это проверка обнаружения/метаданных, не загрузки.
- DownloadHelper просмотрен через content/sidebar.html на ширине 400 px,
  а не через контейнер sidePanel. Карточка и меню доступны без запуска скачивания.
- Viddow на том же источнике: прочитаны настоящий webRequest/storage и
  page-preview.js через scripting. Native-анализ на общей фикстуре не запускался.
- Отдельно прошёл текущий tests/extension_smoke.cjs: настоящая sidePanel,
  подменённый native-порт, сценарии качества, автоподготовки, истории,
  диагностики, двух панелей и ширины 320/400 px. Просмотрены свежие снимки.
- Скорость/успешность скачивания, восстановление обрывов, авторизация,
  реальные аудиодорожки и генерация видеопревью здесь не сравнивались.

## Результаты общей фикстуры

| Свойство | DownloadHelper | Viddow |
| --- | --- | --- |
| Обнаружение HLS | Одна карточка медиа | Один полный адрес master в списке потоков |
| Качество до ручного анализа | 1080p и 720p; смена на 720p отражается в карточке | DOM-сборщик качества не возвращает; нужен анализ источника |
| Длительность | 00:10 | DOM duration=null; duration отсутствует у тестового video |
| Изображение | Заглушка | DOM-сборщик вернул poster тестового video |

Это не доказывает, что backend Viddow не умеет получить качество/длительность.
Проверка показывает различие между автоматическим обнаружением DownloadHelper
и ранними данными Viddow до native-анализа. Наличие 1080p в синтетическом
плейлисте не подтверждает разрешение реального файла: сегмент не загружался.

## Подтверждено чтением кода

DownloadHelper service/main.js содержит разбор HLS EXTINF/RESOLUTION и создаёт
медиа с playlist, duration, master_url, media hash и контекстом запроса.
content/panel.js выбирает изображение media → page → заглушка. Для короткого
превью UI отправляет request_preview с tab_id/media_hash; сервис создаёт файл,
on_preview_available возвращает его имя, UI читает его из origin-private
storage и назначает video blob URL. Сам факт механизма подтверждён; генерация
клипа и путь конкретного кадра пользовательского сайта не проверены.

Viddow popup.js автоматически отправляет на анализ URL верхней страницы даже
при обнаруженном потоке. Неподдерживаемая страница поэтому может дать ошибку,
хотя сам HLS пригоден для анализа. background.js сохраняет полный URL и headers,
но не сохраняет frameId/documentId у потока. page-preview.js не возвращает
идентификатор конкретного video/currentSrc. Этого недостаточно для надёжной
связи DOM-плеера с сетевым потоком при нескольких вложенных плеерах.

## UX-сравнение

- У DownloadHelper компактная карточка: превью, название, качество, скачивание.
  На ширине 400 px основной результат легко охватить взглядом, но подписи мелкие.
- Viddow стал последовательнее относительно прежнего интерфейса: выбор качества
  и аудио объединён, технические потоки свернуты, запуск не уводит в очередь.
- Карточка Viddow всё ещё высока: большая картинка, пояснения, сведения об источнике
  и отдельные поля отодвигают кнопку вниз. Полезно сохранить читаемость, а после
  готовности данных перейти к компактному превью и действиям рядом с качеством.
- Озвучки у Viddow явно представлены в форме; превосходство над конкурентом
  не установлено, поскольку аудиосценарий DownloadHelper отдельно не проверен.

## Следующий приоритет

1. Привязать поток и сведения плеера к вкладке/документу/фрейму/медиа; учитывать
   скрытых предков и неоднозначность. Одного frameId недостаточно при нескольких
   media в одном фрейме; не объединять по имени файла или сайту.
2. Получать метаданные подтверждённого HLS/DASH, используя существующий анализ,
   а не ограничиваться неподдерживаемой верхней страницей. Ограничить число
   запросов, иметь отмену, не выбирать первый пойманный адрес молча.
3. Объединять метаданные того же источника с указанием происхождения полей.
   Для VOD можно исследовать длительность media-плейлиста; длина окна live
   не равна длительности всего эфира. Не подставлять неизвестные значения.
4. Постер страницы, постер video и кадр хранить раздельно. Кадр выбранной серии
   может быть предпочтительнее общего постера. Короткое видеопревью — отдельная
   последующая функция; не делать картинку обязательной для скачивания.
5. Затем уплотнить карточку. Пользователь ранее явно поставил данные раньше
   дальнейшей перестройки компоновки; этот приоритет сохраняется.
